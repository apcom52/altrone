# Аудит зависимостей workspace Altrone

Разбор `package.json` трёх пакетов — `core` (altrone-ui), `mcp` (@altrone/mcp) и `docs` — с проверкой фактического использования в коде, а не только по наличию в манифесте.

**Итог: 37 пакетов всего · 26 оставить · 7 пересмотреть · 4 удалить/заменить.**

Главный вывод: реальных кандидатов на «написать своё» почти нет — большинство runtime-зависимостей решают узкую проблему (позиционирование, drag&drop, парсинг markdown), которую переписывать самим дороже, чем поддерживать чужой пакет. Основная проблема — не «чужой код», а мёртвый вес: неиспользуемые пакеты и рассинхронизация версий между `core` и `docs`.

## Кандидаты на peerDependencies (core)

Правило простое: в `peerDependencies` идёт то, что физически не может дублироваться в дереве потребителя — синглтоны (хуки/контекст ломаются при двух копиях) или то, что должно совпадать между библиотекой и приложением. Всё остальное — обычный внутренний implementation detail компонента и должно оставаться в `dependencies`, чтобы npm поставил его сам.

| Пакет | Сейчас | Должно быть | Почему |
|---|---|---|---|
| `react` | только в `devDependencies` (`19.1.0`, без диапазона) | **peerDependencies**, напр. `>=19.0.0` | В `vite.config.ts` (`rollupOptions.external`) `react`/`react-dom`/`react/jsx-runtime` уже вынесены из сборки — рантайм физически ожидает копию React от потребителя. Но `peerDependencies` в `package.json` вообще не объявлены: npm/yarn не проверит версию у потребителя и не предупредит, если React не установлен вовсе. |
| `react-dom` | только в `devDependencies` (`19.1.0`, без диапазона) | **peerDependencies**, напр. `>=19.0.0` | То же самое — тоже в `external`, тоже синглтон (реконсилер должен быть один на дерево). |

Остальные зависимости — `@floating-ui/react`, `motion`, `dayjs`, `@tanstack/react-table`, `clsx`, `focus-trap-react`, `react-colorful`, `overlayscrollbars-react`, `react-number-format`, `lodash-es`, `rc-util` — не экстернализированы в `vite.config.ts`, встраиваются/ставятся автоматически и не создают риска двух копий синглтона. Переносить их в `peerDependencies` смысла нет — это переложило бы на потребителя ручную установку внутренних деталей реализации.

**Что сделать конкретно:**
1. Добавить в `core/package.json` секцию:
   ```json
   "peerDependencies": {
     "react": ">=19.0.0",
     "react-dom": ">=19.0.0"
   }
   ```
2. `react`/`react-dom` в `devDependencies` не убирать — они всё ещё нужны для локальной разработки, Storybook и тестов; peer- и dev-зависимость на один и тот же пакет — стандартная связка для библиотек.
3. Это изменение публичного контракта пакета (влияет на резолюцию версий у потребителей) — по `changelog.md` заслуживает отдельной записи в `changelogs/v4/`.

1. Удалить `react-hotkeys-hook` (core) и `@dnd-kit/*` (docs) — 0 использований, чистое избавление от веса.

6. Проверить, какие именно утилиты берутся из `rc-util` в DatePicker — заменить точечно, если это 1–2 небольшие функции.
