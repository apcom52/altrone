# Spacing — Semantic Roles

- **Decided**: spacing is a separate concern from `size` (mini/s/m/l/xl) — don't reuse that dictionary for spacing.
- Roles are named by **purpose**, not magnitude: `--space-control-x`/`--space-control-y` (internal control padding — varies by component `size`, a role × size matrix, since radius depends on the same value), `--space-inline` (icon↔text gap), `--space-stack` (vertical rhythm between fields/list items), `--space-content` (padding inside content containers), `--space-section` (gap between large layout blocks), `--space-inset-compact` (dense lists/tables).
- **Implemented**: non-control roles and the control-role matrix (`--space-control-{x,y}-{mini,s,m,l,xl}`) exist as aliases over the existing primitive scale — see `application/styles/_spacing.scss` and `Spacing.stories.tsx`. `NavigationList` and `Tabs.Item` are migrated as zero-diff proof; the ~100 remaining hardcoded-px spots and most of the control-role matrix are not migrated — that's real per-component design review (e.g. `Button`'s per-size padding doesn't match the matrix seed), not a mechanical rename.
- **Still open**: whether to snap `--s-gap` (currently 6px, off the 4px grid, backs the public `Flex`/`Grid` `gap="s"` prop) to 8px, or drop the tier — snapping would make `gap="s"` render identically to `gap="m"`. Needs a design call, don't assume.
