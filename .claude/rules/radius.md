# Border Radius — Concentric Radius Formula

- Formula: `radius_child = radius_parent - gap`, implemented as `clamp(var(--radius-mini), calc(var(--radius-outer) - gap), var(--radius-outer))`.
- Floors at `--radius-mini` (2px) so a wide gap never rounds a corner all the way down to a hard square inside an otherwise-rounded container — **except** when the parent's radius is already at/below that floor (most notably an explicit `--radius-outer: 0`), where `clamp(MIN, VAL, MAX)` naturally resolves to `MAX` (the un-subtracted inherited radius). Don't add extra conditional logic for the zero case — the `clamp` behavior already handles it.
- **Decided**: implement via CSS `calc()`/`clamp()` from inherited custom properties — don't author a parallel static radius-by-size table, or we reproduce the same source-of-truth drift being fixed in spacing.
- To animate radius through a transition, register it via CSS Houdini `@property` (`syntax: '<length>'`) — a plain custom property animates as a string (discretely), not as a length.
- `Box` base case: `shape="rounded"` (default) resolves to `max(var(--radius-outer), var(--radius-mini))` — a `Box` with no ambient radius scope is `2px`, not a hard square. A larger scope / `radius` prop still wins; `shape="rect"` is the way to a true `0`. This floors `--box-radius` only, never `--radius-outer`, and does **not** honour the "explicit 0 stays 0" escape hatch above (use `shape="rect"` instead).
- Reference: `application/styles/_radius.scss` (tokens), `Radius.stories.tsx` (live playground + rationale), `pagination.module.scss` (first real adopter).
