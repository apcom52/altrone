# Altrone 2.2 → 4.0: что потеряно / не реализовано

Сравнение старой версии (`altrone-ui` 2.2.1, `/Users/apcom/tst/altrone-ui/`) и текущей версии в разработке
(`core/` в этом воркспейсе, target-архитектура "v4"). Все находки перепроверены чтением исходников обеих версий
(не только README/сторис). Не включает `useConfiguration()`/`config`-проп (удалены осознанно, см.
`configuration.md`) и смену стиля `ref`-форвардинга (`forwardRef` → plain prop, не потеря).

Структура 2.2 в целом отличается от 4.0: в 2.2 компоненты сгруппированы по категориям
(`containers/data/form/indicators/list/typography`), в 4.0 — плоский список `src/components/<name>`. Ниже —
компоненты и возможности 2.2, которых нет в 4.0.

## Полностью отсутствующие компоненты

- **`PhotoViewer`** (+ `PhotoViewerImage`) — `containers/PhotoViewer`. Полноэкранный лайтбокс поверх портала:
  зум (`min`/`max`, `zoomIn`/`zoomOut`), перетаскивание увеличенного фото (через внутренний `Draggable`),
  переключение фото, разворачиваемое описание (`expanded`, дефолт из `options.photoViewer.openDescriptionByDefault`),
  адаптивная toolbar. В 4.0 `Image` — это только одна картинка с preloader/broken-fallback, без галереи/zoom/лайтбокса.
  Внутренний `Draggable` (`containers/Draggable`, drag по экрану/локально через `DraggablePosition`) использовался
  только здесь и тоже отсутствует.

- **`Carousel`** (+ `CarouselItem`) — `data/Carousel`. Слайдер с бесконечной прокруткой (`loop`), автопрокруткой
  по таймеру (`duration`, мин. 500 мс), `imageFitting`, встроенной интеграцией с `PhotoViewer` (`usePhotoViewer` —
  кнопка "развернуть" в тулбаре открывает текущий слайд в лайтбоксе), учётом `reduceMotion`. В 4.0 аналога нет
  вообще ни в каком виде (ни слайдера, ни галереи).

- **`ScrollableSelector`** — `form/ScrollableSelector`. Колесо выбора в iOS-стиле: список опций со
  scroll-snap-навигацией, автоскролл к выбранному значению (`scrollTo({ top, behavior: 'smooth' })`),
  кастомизируемый рендер опции (`ScrollableSelectorOptionComponent`). В 4.0 нет ни этого компонента, ни похожего
  паттерна (ближайшее — `Select`/`DatePicker`, но это не тот UX).

- **`CheckboxList`** — `form/CheckboxList`. Обёртка над несколькими `Checkbox`, которая сама сворачивает список
  по `limit` (по умолчанию 5) и добавляет кнопку "показать ещё" / "меньше" (`t('common.more'/'common.less')`).
  В 4.0 `Checkbox` не имеет группового контейнера с таким поведением; `CollapsedList` решает похожую, но более
  узкую задачу (авторазворачивание произвольного списка, не специфично для чекбоксов).

- **`RadioList`** — `form/RadioList`. Готовая обёртка "options-массив → список `Radio`" (`options: Option<T>[]`,
  `value`, `onChange`, `direction`). В 4.0 есть compositional `Radio`/`Radio.Item` (см. ниже, "Изменившийся, но не
  потерянный функционал"), но именно `options`-driven обёртки (данные → готовый список без ручного `.map()`) нет.

- **`ButtonContainer`** — `containers/ButtonContainer`. Простой layout-контейнер для группы кнопок
  (`direction`, `align`, `mobileFluid` — растягивание кнопок в column на мобильном). В 4.0 отдельного компонента
  нет; тривиально заменяется на `Flex`, но `mobileFluid` (авто-фулвайд кнопок на мобильном без ручного медиа-запроса)
  придётся реализовывать самостоятельно.

- **`Blockquote`** — `typography/Blockquote`. Семантическая цитата (`<figure>`/`<blockquote cite>`/`<figcaption><cite>`)
  с атрибуцией автора (`author`) и кастомизацией вложенных классов/пропсов (`classNames`, `innerProps`). В 4.0 нет
  ни отдельного компонента, ни варианта в `Text` — цитату с автором придётся вручную собирать из сырых HTML-тегов,
  что противоречит `altrone-ui-usage.md`/`components.md` (использовать только компоненты библиотеки).

- **Настоящий заголовок (`Heading`, `<h1>`–`<h6>`)** — `typography/Heading`. Рендерил реальный семантический тег
  уровня 1–6 (`React.createElement('h'+level, ...)`). В 4.0 `Text` — полиморфный компонент, но без варианта,
  рендерящего `<h1>`–`<h6>`: доступны только `<span>` (по умолчанию), `<p>` (`block`), `<ol>`/`<ul>`/`<li>`
  (`list`/`item`), `<a>` (`href`). Это реальная просадка accessibility/SEO — нет способа получить корректную
  иерархию заголовков документа через компоненты библиотеки (`Text.md` подтверждает: только `size`/`weight`
  меняют внешний вид, тег остаётся `<span>`/`<p>`).

- **Декларативное меню по данным (`ContextMenuType`)** — `types/ContextAction.ts` + `list/ContextMenu`. В 2.2 это
  был центральный, широко переиспользуемый механизм: массив описаний действий
  (`ContextClickAction`/`ContextCheckboxAction`/`ContextRadioListAction`/`ParentContextAction` с вложенными
  подменю/`SeparatorAction`), который принимался как проп и рендерился в виде floating-меню — без ручной сборки
  JSX. Был встроен в:
  - `Button.dropdown` (кнопка с меню одной строкой, `dropdown={[...]}`);
  - `Toolbar`/`ToolbarGroup`/`ToolbarAction`/`ToolbarMenu` (`contextMenu`/`submenu`);
  - `NavigationList`/`NavigationListItem` (`action.contextMenu` — контекстное меню на пункте списка);
  - `Breadcrumbs` (свёрнутые крошки превращались в `ContextMenuType` для показа в меню);
  - `DataTableAction` (`contextMenu` — превращает кнопку действия в меню).

  В 4.0 весь этот функционал заменён на полностью compositional `Dropdown`/`Dropdown.Menu`/`Dropdown.Action`/
  `Dropdown.Checkbox`/`Dropdown.ChildMenu` (см. `Dropdown.md`) — то есть меню теперь **обязательно** собирается
  вручную JSX-разметкой, а не передаётся как сериализуемая структура данных. Ни у `Button`, ни у `Toolbar`,
  ни у `NavigationList`/`Breadcrumbs`/`DataTable.RowAction` нет прямого "дай мне массив экшенов — получи меню"
  пропа. Это осознанная архитектурная замена, но конкретная возможность ("построить меню из данных без JSX",
  включая случай, когда список действий приходит с бэкенда как JSON) — потеряна.

- **Триггер меню по правому клику (native `contextmenu`)** — в 2.2 `NavigationListItem` открывал `ContextMenu`
  по `onContextMenu`-событию (настоящее контекстное меню браузера, замещаемое кастомным). В 4.0 у `Dropdown`
  список триггеров жёстко ограничен `'click' | 'focus' | 'hover'` (`Dropdown.md`) — варианта
  `contextmenu`/right-click нет вообще, то есть "настоящее" контекстное меню (по правому клику) в принципе нельзя
  собрать штатными средствами библиотеки.

- **Селективные chips как форм-контрол** — `list/Chips`. Это был именно **input**-компонент выбора одного/нескольких
  значений из списка в виде "таблеток" (`options`, `values`, `onChange`, `multiple`, `SelectedIcon`) — аналог
  `Checkbox`/`Radio`-группы, но в виде чипов. В 4.0 есть только `Tags`/`Tags.Item` (`Tags.md`) — это чисто
  презентационный список меток (ссылка/кнопка/статичный текст), без состояния "выбрано"/`values`/`onChange` и без
  режима `multiple`/`single`. Как элемент управления формой (мультивыбор чипами) — функциональность отсутствует.

- **Мобильный fallback floating-элементов в модалку** — `containers/FloatingBox`
  (`FloatingBoxMobileBehaviour.modal`). На мобильных экранах (`ltePhoneL`) floating-панель (использовалась под
  капотом в `Select`, `DatePicker`, `Button.dropdown` и т.д.) могла автоматически превращаться в полноэкранную
  `Modal` вместо маленького прижатого к триггеру попапа — так удобнее для тач-интерфейсов. В 4.0 у `Popover`/
  `Dropdown` такого автоматического переключения в модалку на мобильных нет (`Popover.md`/`Dropdown.md` не
  упоминают mobile-режим) — на маленьких экранах все floating-оверлеи ведут себя как на десктопе.

- **Сегментированный `Progress`** — старый `Progress` поддерживал `ProgressVariant`-режим с дискретными
  сегментами (`ProgressSegmentComponent`, кастомный рендер каждого активного/неактивного сегмента — например,
  прогресс по шагам визарда). В 4.0 `Progress` — только сплошная полоса (`value`/`min`/`max`, `activeClassName`/
  `activeStyle`), сегментного режима нет (`Progress.md`).

- **Область поведенческих дефолтов `AltroneOptions` со scoped-переопределением** — `hocs/Altrone` +
  `hocs/AltroneConfig`. Это отдельная от стилей (`className`/`style`) система: дерево *поведенческих* настроек
  по умолчанию (`global.reduceMotion`, `global.transitionDuration`, `numberInput.useFormatFromLocale`,
  `carousel.reduceMotion`, `modal.reduceMotion`, `floatingBox.offset`/`windowOffset`,
  `photoViewer.openDescriptionByDefault`, `spoiler.reduceMotion`), которую можно было переопределить не только
  глобально (`<Altrone options={...}>`), но и локально для поддерева (`<AltroneConfig options={...}>` — глубокий
  `merge` поверх родительских опций). В 4.0 `prefers-reduced-motion` обрабатывается только глобально через
  `MotionConfig`/CSS-медиазапрос (`motion.md`) — механизма точечно переопределить поведенческий дефолт
  (не стиль) для одного поддерева дерева компонентов не осталось. Отдельно от уже задокументированного удаления
  `useConfiguration()` (`configuration.md`), которое касалось только `className`/`style`.

- **`BasicInput`** — `form/BasicInput`. Публичный базовый "конструктор" для кастомных полей ввода: давал готовую
  обвязку `errorText`/`hintText`/`size`/invalid-стилизацию, чтобы собрать свой инпут с тем же внешним видом
  ошибки/подсказки, что и у штатных полей библиотеки. В 4.0 такого публичного примитива нет — `errorText`/`hintText`
  реализованы отдельно и не переиспользуемо внутри каждого инпута (`TextInput`, `NumberInput` и т.д.), собрать
  полностью кастомное поле с идентичной библиотечной подсветкой ошибки/подсказки штатными средствами нельзя.

## Компоненты с потерянными возможностями

- **`Button` (old → new)** — потеряны:
  - Семантическая роль `role: 'success'` (`types/Role.ts`) — зелёная кнопка "успешное завершение действия"
    (пример из документации 2.2 — кнопка "Save"). В 4.0 `variant` — только `'default'|'submit'|'text'`, а
    цветовой акцент — только `danger?: boolean` (красный); отдельного семантического success-варианта нет
    (`Button.md`).
  - `progress?: number` — числовой прогресс-бар поверх кнопки (отдельно от булева `loading`). В 4.0 `state`
    поддерживает `'idle'|'loading'|'succeeded'|'failed'`, но не произвольное числовое значение прогресса.
  - `elevation?: Elevation` — прямой контроль тени/уровня кнопки. В 4.0 нет такого пропа у `Button`.

- **`NumberInput` (old → new)** — потерян `useFormatFromLocale` (дефолт `true`): автоматический выбор разделителя
  групп разрядов/десятичного разделителя через `Intl.NumberFormat(locale)` в зависимости от активной локали
  приложения. В 4.0 `groupingDelimiter`/`decimalDelimiter` — статичные пропсы с дефолтами `' '`/`'.'`,
  автоматической синхронизации с локалью нет (`NumberInput.md`). Отдельно, уже осознанно и явно
  задокументировано в `NumberInput.md` удаление кнопок степпера (`showControls` в 2.2) — это сознательное
  решение новой версии, а не пропущенный гэп.

- **`Toolbar`/`ToolbarAction`/`ToolbarGroup` (old → new)** — потеряна интеграция с `ContextMenuType` (см. выше);
  функциональность "меню от Toolbar" сохранена, но только через ручную JSX-композицию с `Dropdown`.

- **`DatePicker` (old → new)** — не потеряно по существу: и `RangePicker`, и `MonthPicker`/`YearPicker` есть в
  4.0 (`DatePicker.md`), причём реализация богаче (на `dayjs`). Из потерь — только встроенное `dropdown`-меню
  выбора режима (день/месяц/год) через `ContextMenuType`, что относится к общей потере декларативных меню выше.

## Изменившийся, но не потерянный функционал (другой API, та же задача)

- **`Icon` (строковая, по имени) → нет прямого эквивалента** — старый `Icon` (`typography/Icon`) рендерил
  Google Material Symbols по строковому имени лигатуры (`<Icon i="cancel_presentation" style="outlined" />`).
  В 4.0 библиотека полностью перешла на `lucide-react`: все компоненты принимают готовый `icon?: ReactElement`
  вместо строки. "Показать произвольную иконку по строковому имени" как публичный паттерн — потерян (актуально,
  например, для конфигураций, где имя иконки приходит из БД/CMS как строка); заменяется на явный импорт
  React-компонента иконки. Компенсируется более узким `useIcons()`/`Application.icons` — переопределение
  фиксированного набора служебных иконок, не универсальный механизм "иконка по имени".
- **`RadioList` (options-массив) → `Radio`/`Radio.Item` (compositional)** — в 4.0 нужно вручную маппить массив
  опций в `Radio.Item`; готовой "options → JSX" обёртки, как раньше, нет (см. выше, в разделе "Полностью
  отсутствующие компоненты").
- **`Switcher` → `Switch`** — переименование, тот же функционал.
- **`TabList` → `Tabs`** — переименование, в 4.0 существенно богаче (не потеря).
- **`Chips` (отображение) → `Tags`** — как список меток для чтения (не как форм-контрол выбора) функциональность
  сохранена и даже расширена (`href`/`onClick`/`asChild`), см. про потерю выбора выше.

## Не проверялось / вне области сравнения

- Полное API `DataTable`, `Select`, `Calendar`, `FilePicker`, `Search`, `Spoiler` — точечно сверены (см. текст
  выше), явных потерь функциональности не найдено, в 4.0 эти компоненты в целом богаче версии 2.2.
- Локализация: в 2.2 было только два словаря (`en`, `ru`), в 4.0 — восемь (`en`, `ru`, `fr`, `de`, `es`, `zh`,
  `pt`, `tr`) — расширение, не потеря.
