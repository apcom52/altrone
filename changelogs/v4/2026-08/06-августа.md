## Категориальная палитра + точечные цветовые токены

Добавлена категориальная (qualitative) палитра из 10 цветов (`--category-1..10`, `colors/_categorical.scss`) — для раскраски однотипных элементов по идентичности (аватар человека, тег), а не по смыслу, как у статусов. Портирован `orange` (не существовал раньше) как 10-й хью, вместе с уже добавленным ранее `green`. Выбор цвета — не проп, а детерминированный хэш идентификатора (`ColorUtils.getCategoricalColorIndex`, `src/utils/ColorUtils.ts`): один и тот же человек/тег всегда получает один и тот же цвет без явного выбора. Подключено к `Avatar` — при отсутствии явного `backgroundColor` цвет фона теперь берётся из категориальной палитры по полному имени.

`Tags`/`Badge`/`Calendar` намеренно не тронуты: у `Badge` вообще нет своего цвета заливки (просто форма, цвет задаёт родитель), `Tags.Item` — обычная подчёркнутая ссылка без фона, у `Calendar` нет понятия категории событий в принципе. Подключить категориальные цвета к ним — отдельная задача на дизайн нового API компонента, не подключение токена.

Также добавлены точечные токены: `--color-overlay-scrim` (общий для `Modal`/`Drawer`, вместо дублирования `--black-a3` в каждом отдельно; заодно убрана мёртвая переменная `--modal-backdrop-background-color`, ссылавшаяся на несуществующий `--backdropColor`), `--color-header-backdrop` (вынесен из инлайна в `screen.module.css`, подложка `Screen.Header` осталась акцентной — так решено осознанно, не нейтральной), `--color-selection` (фон `::selection`, подключён глобально).

Зачем: убирает последние открытые точечные вопросы из `.claude/rules/color.md` (кроме `forced-colors`, который отложен отдельно) и даёт `Avatar` осмысленную раскраску по умолчанию вместо одного плоского нейтрального цвета для всех.
