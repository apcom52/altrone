## Чистка legacy `.AltroneDark` + найденный и починенный баг с мёртвыми переменными

Убран класс `.AltroneDark` — `AltroneApplication` больше не выставляет ни `classList.toggle`, ни `clsx`-флаг. Тема теперь только через `data-altrone-theme`: на корневом элементе (как и раньше, через React-проп) и дополнительно на `<html>` (через `useLayoutEffect`, было `useEffect` — тоже баг из `application/ROADMAP.md`, попутно исправлен) для глобальных нескоуп-стилей (`::selection` и т.п.) и порталов вне `data-altrone-root`.

При миграции 6 файлов, реально использовавших `.AltroneDark`-селектор (`NavigationList` group/link action, `Popover`, `Select`, `DataTable` header/filtering), обнаружилось: все они ссылались на `var(--default-N)`/`var(--primary-N)`/`var(--danger-N)` — переменные, определённые только в `core/src/components/application/index.css`, который нигде не импортируется в приложении. То есть их тёмная (местами и часть светлой) тема уже не работала. Тот же баг нашёлся ещё в `Calendar`, `ColorPicker`, `FilePicker`, `Range`, `DatePicker`, одной Storybook-истории `Popover` и общем Storybook-хелпере `gridCell` — везде переведено на реальные токены (`--text-*`, `--background-*`, `--interactive-*`, `--accent-N`, `--danger-text-1`, `--disabled-text-color`). Поскольку эти токены уже сами по себе меняются по теме, большинству файлов больше не нужен отдельный dark-блок — осталось одно объявление на обе темы.

Реализован FOUC-скрипт: `getThemeInitScript(initialTheme)` — `AltroneApplication` рендерит его первым в своём выводе, скрипт повторяет логику `resolveInitialTheme` и синхронно выставляет `data-altrone-theme` на `<html>` до отрисовки остального дерева. Это best-effort в рамках компонента, не гарантия для любого стриминг-SSR — для гарантии потребителю нужно вставить `getThemeInitScript()` в свой `<head>` самостоятельно.

Решено НЕ переходить на `light-dark()`/`color-scheme` — риск переписывания всех цветовых файлов ради архитектурной чистоты без функциональной пользы признан неоправданным.

При правке нашлась и исправлена регрессия в собственном юнит-тесте (`application.test.tsx`), явно проверявшем наличие класса `.AltroneDark` — тест переписан на проверку атрибута `data-altrone-theme`.

Зачем: закрывает оба открытых вопроса T-170 и попутно чинит реальный, ранее незамеченный баг — 10+ компонентов рендерили нерабочую тёмную тему (и местами светлую) из-за ссылок на несуществующие переменные. Часть архитектурного рефакторинга v4 (`ARCHITECTURE-V4.md`, `.claude/rules/dark-theme.md`), Linear T-170.

## Экспорт `getThemeInitScript`, `Theme`, `Accent`, `Language` из публичного API

`getThemeInitScript` и типы `Theme`/`Accent`/`Language` существовали, но не были доступны потребителю — не экспортировались из `core/src/components/application/index.ts`. Обнаружилось при написании Storybook-истории `Foundations/Dark Theme`: документировать использование `getThemeInitScript()` в чужом `<head>` не имело смысла, если его нельзя импортировать. Добавлена документационная история с живым переключателем темы.

Зачем: без экспорта FOUC-скрипт из T-170 был бесполезен вне самого `AltroneApplication`, а `Theme`/`Accent`/`Language` — давно известный пробел (`application/ROADMAP.md`). Часть архитектурного рефакторинга v4, Linear T-170.
