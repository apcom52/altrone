## `TextInput` и его острова переведены на примитив `Box`

`TextInput` теперь рендерится как `Box` — визуальная рамка (заливка, обводка, скругление,
elevation, фокус-кольцо во время ввода) целиком принадлежит примитиву. В собственном
стайлшите остались только типографика по размерам, flex-ряд, раскладывающий острова вокруг
`<input>`, сброс самого `<input>` до прозрачного и два состояния, которых у `Box` нет —
`readonly` и `disabled`. Все острова мигрированы на React 19 (`ref` как обычный проп, без
`forwardRef`). `ActionIsland` — это `<Button variant="default">` (см. ниже); пассивные
`TextIsland`/`IconIsland`/`CustomIsland`/`LoadingIsland`/`CharCounterIsland` — простые
`<div>` (Box им ничего не давал, только токены отступов/размера, которые и так приходят
через каскад).

Ломающие изменения в публичном API:

- **`placement` островов: `'left' | 'right'` → `'start' | 'end'`.** Значения по умолчанию —
  `start`. Старые `left`/`right` больше не принимаются (v4 допускает ломающие изменения).
- **`ref` теперь указывает на визуальную обёртку**, а не на `<input>`. Для доступа к самому
  полю добавлен проп **`inputRef`**. Затронуты обёртки: `PasswordInput`, `Search`,
  `AutocompleteInput` (у всех `ref` → обёртка, `inputRef` → `<input>`); `NumberInput` и
  `ColorPicker` продолжают резолвить свой `ref` на поле через собственную обвязку.
- **`variant` → `material` + `tone`**: `default` → `plate`/`neutral` (матовая подложка с
  тонкой обводкой, как у дефолтного `Button`), `transparent` → `transparent`/`neutral`;
  `invalid` → `tone="danger"`.
- **`transparent` подсвечивает фон при наведении и фокусе — одинаково**
  (`--box-tone-translucent`, т.е. `--interactive-a1` для нейтрального тона), как
  `text`-кнопка. У `Box` `editable` ховера нет вовсе, а `:focus-within` давал *усиленную*
  заливку (`--box-tone-translucent-strong`) — фон заметно темнел, когда курсор попадал в
  поле. Оба состояния приведены к обычному `--box-tone-translucent` локальным правилом в
  `textInput.module.scss`. Восстанавливает поведение прежнего `.Transparent:hover`.

Поведение и внутреннее устройство:

- **Убран `ResizeObserver` и инлайновый расчёт `padding`.** Раньше отступы `<input>`
  подгонялись под ширину контейнеров островов через JS-измерение; теперь `<input>` и острова
  лежат в одном flex-ряду в нормальном потоке — без измерений, без клиентского кода, без
  риска SSR-рассинхрона.
- Удалён мёртвый `useBoolean` focus/blur (никто не читал `focused`).
- Фокус-кольцо переехало с `<input>` на обёртку (`Box` `editable` → `:focus-within`) —
  теперь подсвечивается весь контрол.
- Пассивные острова — компактные inline-чипы без собственного горизонтального паддинга;
  зазор от края поля задаётся контейнерами `.StartIslands`/`.EndIslands` (см. ниже).
  Исключение: `TextIsland`/`IconIsland`/`LoadingIsland`/`CharCounterIsland`, стоящий
  вплотную к краю (первый в `start` / последний в `end`), получает дополнительные
  `--space-inset-compact` слева/справа, чтобы не смотреться тесно у самой границы.
  Размер иконки/текста наследуется из `--text-input-icon-size`/`--text-input-font-size`
  поля.
  `ActionIsland` (Button) — на один размерный тир меньше поля (`m` → `s`, пол — `mini`).
- Контейнеры островов получают отрицательный внешний отступ
  `calc(var(--text-input-island-outer-inset) - var(--box-padding-x))` — подтягивают
  остров внутрь на собственный горизонтальный паддинг поля (`--box-padding-x`, растёт по
  размеру: 4/6/8/12/24px), оставляя ровно `--text-input-island-outer-inset` зазора между
  краем поля и контентом острова (по умолчанию `--space-inset-compact` = 4px; острова
  своего паддинга не имеют). Без таблицы по размерам. У `mini`
  `--text-input-island-outer-inset` обнулён: там высота острова равна высоте поля (нет
  вертикального запаса), поэтому горизонтально остров тоже вплотную к краю.
- **Высота поля = ровно размерный тир** (`min-height: var(--box-size)`, 32px для `m`).
  У обёртки `Box` вертикальный паддинг обнулён (`padding={{ y: 0 }}`), поэтому острова
  больше не раздувают поле (раньше `m` с островами вырастал до ~40px). Горизонтальный
  паддинг — прежний, от размерного тира.
- **`ActionIsland` теперь рендерит `<Button variant="default">`** вместо собственной
  композиции `Box` + `<button>`. Приняты его пропы (`Omit<ButtonProps, 'variant'>` +
  `placement`), поэтому острову-кнопке доступен весь функционал `Button`: `state`
  (`loading`/`succeeded`/`failed`), `badge`, `tooltip`, `selected`, `additionalIcon`.
  `variant` залочен на `default` (`plate`), `size` по умолчанию — на тир ниже поля.
  Следствия: только с иконкой (`showLabel={false}`) → круглая кнопка + автоматический
  `Tooltip` с `label` (раньше был нативный `title`); нажатие даёт `whileTap` scale, как
  у обычной кнопки. `action.module.scss` удалён.
- **`disabled` поля дизейблит `ActionIsland`** внутри него (через новый
  `TextInputDisabledContext`): проп `disabled` острова OR-ится с `disabled` поля, так что
  у кнопки появляется настоящее disabled-состояние (атрибут + вид), а не только
  `pointer-events: none` от обёртки.
- `LoadingIsland`: добавлен локализованный `aria-label` (ключ `textInput.loading` во всех
  пяти словарях).
- `disabled` у поля — токены `--disabled-background` / `--disabled-text-color`.
- Из `.scss` убраны `@import 'src/global/mixins'` и статические таблицы
  `--text-input-size` / `-rounding` / `-*-padding` / `-*-background` по размерам (их роль
  взял `Box`).

Зачем: `Box` задуман как общий визуальный примитив chip-подобных контролов; `TextInput` —
второй крупный потребитель после `Button`. Это убирает дублирование логики материалов и
elevation, снимает JS-измерение раскладки (плюс к SSR-совместимости) и приводит компонент к
правилам v4 (React 19 ref, семантические spacing-токены, доступность). Переименование
`left/right` → `start/end` — под будущую поддержку RTL и в единый словарь с остальными
компонентами.

## `Text` с `block` — прозаический интерлиньяж по умолчанию

У абзацев (`<Text block>` → `<p>`) появился дефолтный `line-height: 1.6` (переменная
`--text-block-line-height` в `text.module.scss`) — заметно свободнее, чем тесные
пер-размерные токены `--line-height-*`. Явно заданный `size` по-прежнему перебивает его
(правило `.SizeN` идёт ниже по файлу), поэтому заголовки, собранные как `<Text block
size={6} weight="bold">`, не меняются.

Зачем: без явного размера `block`-абзацы наследовали `line-height` от контейнера или
получали тесный `--line-height-4` — тело статьи/описания в сторис читалось слишком плотно.
1.6 — стандартная величина для основного текста.
