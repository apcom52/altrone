## Storybook: группа `Components/Core`

`Text`, `Screen` и `Box` переехали из `Components/Typography` / `Components/Containers` /
`Components/Atoms` в общую группу **`Components/Core/*`** — это базовые примитивы, на которых
строится остальная библиотека, и держать их вместе удобнее, чем разбросанными по
категориям.

Истории `Text` переписаны в article-стиль (`storybook.md`): вместо трёх разрозненных
демо — четыре самостоятельных «артефакта» с прозой, показывающие компонент в деле:
«Type & anatomy» (полиморфизм тег↔проп, шкала размеров, вес), «A formatted document»
(документ целиком из `Text` + `Flex`, все inline-марки в реальном тексте), «Under layout
pressure» (`truncate` / `lineClamp` / `nowrap` / semantic `color` в узкой колонке),
«Polymorphism & asChild» (`asChild` поверх `button`/`label`/`input`, `href`/`external`,
`align`).

Зачем: старые истории были скудными и не передавали, зачем нужен единый текстовый
примитив. Публичный API `Text` не менялся.

## Истории `PasswordInput` и `NumberInput` — переписаны

Плоские демо заменены на реалистичные сценарии (article-стиль, `storybook.md`):

- **PasswordInput** — «Creating a password» (регистрация: reveal-тоггл, живой индикатор
  силы, чеклист требований, проверка совпадения) и «Editing secret values» (редактор
  env-секретов: `KEY` + скрытое значение, reveal + `Copy` action-island).
- **NumberInput** — «An order, line by line» (позиции заказа: количество с
  `min`/`max`-клампом, производные суммы, итог через read-only currency-форматированное
  поле) и «Money, formatted as you type» (`groupingDelimiter`/`decimalDelimiter` для US и
  EU локалей, `digitsAfterPoint` + `fixedDecimalScale`, тихий `max`-кламп).

Публичный API `PasswordInput` не менялся; по `NumberInput` — см. следующий раздел.

## `NumberInput`: спиннер удалён

Кнопки `+` / `−` внутри `NumberInput` убраны полностью — вместе с пропом `showControls`,
компонентом `Spinner`, `inner/`-папкой и локали-ключами `numberInput.increase` /
`numberInput.decrease` (секция `numberInput` в словарях удалена).

Зачем: зона попадания у стека из двух микро-стрелок — 24×12px (меньше на `s`), это
нарушает собственное правило доступности «≥24px», а клавиатурного эквивалента у
`type="text"`-поля от `NumericFormat` нет вообще. Степпер оправдан только для малых
величин с частой правкой ±1 (количество в корзине) — и там нужен явный крупный
`[−] / [+]`, а не стрелки в поле. Кто использовал спиннер — собирает такой степпер сам
на `TextInput.ActionIsland`.

Заодно:

- **`ref` → визуальная обёртка, `inputRef` → `<input>`** — приведено к тому же контракту,
  что у `TextInput` / `PasswordInput` (раньше `ref` резолвился на input через
  `getInputRef`).
- **`fixedDecimalScale` теперь работает** — проп был в типах, но не прокидывался в
  `NumericFormat`.
- **Острова внутри `NumberInput` больше не теряются** — `children` раскрывались как
  `{safeChildren}` (вложенный массив, не проходил `isValidElement`-фильтр `TextInput`),
  теперь `{...safeChildren}`, как в `PasswordInput`.

## Истории `AutocompleteInput`, `Search`, `Textarea` — переписаны

Плоские демо (в т.ч. живой `fetch` на внешний API прямо из сторис) заменены на
самостоятельные реалистичные сценарии:

- **AutocompleteInput** — «A command palette» (⌘K-палитра: `renderSuggestion` с иконкой,
  подсветкой совпадения, секцией и хоткеем; стрелки двигают выделение через
  `usePopoverCurrentIndex`) и «Address lookup against a slow API» (медленный async
  `getSuggestions` + спиннер-остров, `minChars=3`, `cacheResults` со счётчиком запросов,
  тумблер сбоя API → `onError`).
- **Search** — «Search-as-you-type in a docs sidebar» (поиск по индексу страниц с
  хлебными крошками и сниппетом, подсветка совпадения, пустое состояние) и «Filtering a
  list» (Search без dropdown — просто поле-фильтр с иконкой, оверлеем-плейсхолдером и
  кнопкой очистки, гоняющее фильтр по списку).
- **Textarea** — «Writing a comment» (компактный composer: resize-хендл, живой счётчик,
  `invalid` за лимитом, хоткей-подсказка) и «A profile field, edited in place»
  (settings-поле с циклом read-only → edit (min-length gate) → save).

Заодно: **`Search` стал generic — `Search<T>`** (как `AutocompleteInput`), `T` по
умолчанию `string`. Раньше `SearchProps` фиксировал `string`, и объектные подсказки с
`renderSuggestion` не типизировались.

## Ещё истории для form-компонентов

К уже переписанным добавлены разнообразные сценарии (по 1–2 на компонент):

- **TextInput** — «Editing a value in place» (inline-edit ячейки: `transparent`-поле, фокус
  через `inputRef`, Enter/Esc) и «One-time code» (6 полей `size="l"` c авто-переходом,
  Backspace-назад и paste-по-строке).
- **PasswordInput** — «Unlock screen» (auth-гейт: ошибка + счётчик попыток, поле
  дизейблится) и «Suggest a strong password» (генератор: два action-острова
  Regenerate/Copy, `Switcher` на символы).
- **NumberInput** — «Split the bill» (валюта + integer + процент в одной форме, производный
  итог) и «Port forwarding rules» (integer `min=1 max=65535`, предупреждение о
  привилегированных портах и дубликатах вне поля).
- **AutocompleteInput** — «Assign a task» (объектные подсказки строками с аватарами;
  выбор сворачивает поле в чип, текущий ассайни отфильтрован).
- **Search** — «Search everything» (один индекс из people / docs / channels / settings,
  у каждого типа своя иконка и хвостовой лейбл).
- **Textarea** — «Paste a config» (высокое поле `size="l"` под JSON с живой проверкой
  валидности и счётчиком строк) и «Compose & preview» (write/preview split: одна строка
  кормит редактор и `Text`-превью с block-версткой).

Компоненты не менялись.

## `AutocompleteInput`: `renderSuggestion` рендерит только содержимое строки

`renderSuggestion` больше не возвращает интерактивный элемент целиком — теперь это
рендерер **содержимого** строки. Сам `AutocompleteInput` в обоих режимах (со
`renderSuggestion` и без) оборачивает подсказку в свою строку-кнопку, которая берёт на
себя регистрацию в списке (`useListItem`), цель клика, навигацию с клавиатуры и
скользящую подложку hover/выделения — ту же, что в пунктах `Dropdown`.

Ломающие изменения API:

- `renderSuggestion: (ctx) => ReactElement` → `(ctx) => ReactNode`, возвращает
  внутренние элементы строки, а не `<button>`.
- Из `AutocompleteRenderSuggestionContext` убран `onSelect` — выбор делает обёртка
  строки: клик или `Enter` пишет `getSuggestionValue(suggestion)` в поле и вызывает
  проп `onSelect`. Потребителю больше не нужны `useListItem` / `usePopoverCurrentIndex`
  и ручной инлайновый фон активного элемента.
- Дефолтный режим (без `renderSuggestion`) рендерит собственную строку
  `AutocompleteSuggestion` вместо `Dropdown.Action`.

Общий примитив: логика подложки вынесена из `dropdown/useDropdownItemHover` в
`utils/useOverlayItemBackground({ popoverId, className })` — общий скользящий
hover/focus-хайлайт для пунктов оверлейных списков. `useDropdownItemHover` теперь
тонкий адаптер над ним (пункты `Dropdown` визуально не изменились).

Зачем: при кастомном `renderSuggestion` подложка выделения не рисовалась вовсе, и
каждый потребитель вручную повторял регистрацию пункта, чтение активного индекса и
подсветку. Теперь это забота компонента, а рендерер отвечает только за вид строки.

Заодно: в `AutocompleteInput` добавлена история «Pick a font — the default
renderer» — единственная без `renderSuggestion`: строковые подсказки, дефолтный
рендер строки (с той самой скользящей подложкой), выбор пишет строку в поле,
payoff — превью sample-текста выбранным шрифтом.

## `TextInput`: проп `shape`; у `Textarea` углы `rounded` вместо `pill`

У `TextInput` появился проп `shape` (`BoxShape`: `rect`/`rounded`/`squircle`/`circle`/`pill`),
по умолчанию `'pill'` — прежнее поведение. `Textarea` переопределяет его на `'rounded'`
и сидит радиус `--radius-outer: var(--radius-xl)` (16px) на своей обёртке.

Зачем: `pill` тянет углы в капсулу по половине высоты — для однострочного поля это
правильно, но `Textarea` растёт вертикально и с `pill` получала огромные круглые торцы,
визуально выпадая из ряда с `TextInput`/`Select`/`DatePicker`. 16px — это ровно тот угол,
в который `pill` разрешается на контроле дефолтного размера (`m`, 32px), так что
`Textarea` остаётся в той же «семье» форм, но радиус фиксированный и не искажается на
высоком поле. `rounded` берёт величину из `--radius-outer` (без сида дал бы 0/rect),
поэтому сид задаётся в `textarea.module.scss`.

Заодно `Textarea` получила внутренний вертикальный отступ (`padding-block:
var(--space-control-y-m)`) — на самом `<textarea>`, чтобы он скроллился вместе с
текстом. `TextInput` зануляет вертикальный паддинг обёртки (однострочное поле =
ровно высота размера), а многострочному тексту так упирается в край.

## Острова `TextInput` на `Textarea` — починены и раскладываются футером

Два изменения, чтобы связка `<Textarea><TextInput.CharCounterIsland/></Textarea>`
(она есть в доке) вообще заработала:

- **Баг**: `Textarea` отдавал детей в `TextInput` как `<textarea/>{children}`, из-за
  чего острова приходили вложенным массивом одним уровнем глубже, а
  `filterNodes()` в `TextInput` выбрасывал весь этот массив — острова не
  доходили. Теперь `{...safeChildren}` (как в `PasswordInput`).
- **Раскладка**: когда поле оборачивает `<textarea>` (`.Field:has(textarea)`),
  острова больше не делят строку с полем (это укорачивало бы каждую перенесённую
  строку, а start-остров сдвигал бы весь текст вправо), а встают футером под
  текстом — `<textarea>` на всю ширину, острова строкой ниже (`placement="start"`
  слева, `placement="end"` справа через `flex-wrap` + `margin-left: auto`).

Показано в истории `Textarea` → «Writing a comment» (hint отправки + счётчик
символов как острова-футер).

Заодно: в `Components/Containers/Form` добавлена история «Every field, one form —
onboard a new hire» — по одному контролу на каждый тип вопроса (`TextInput`/`Select`/
`NumberInput`/`DatePicker`/`AutocompleteInput`/`Textarea`/`PasswordInput`/`Switcher`),
плюс `Search` над формой в роли «найти и подставить запись», а не поля ввода.
