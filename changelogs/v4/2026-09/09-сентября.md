## Логотипы компонентов и отдельный вход `altrone-ui/logos`

Добавлена папка `core/src/logos/` с SVG-логотипами почти для всех компонентов библиотеки
(`application`, `screen`, `box`, `button`, `text-input`, `select`, `checkbox`, `radio`,
`switcher`, `range`, `date-picker`, `calendar`, `color-picker`, `file-picker`, `data-table`,
`dialog`, `modal`, `drawer`, `popover`, `dropdown`, `tooltip`, `tabs`, `breadcrumbs`,
`pagination`, `navigation-list`, `bottom-navigation`, `side-navigation`, `avatar`, `tags`,
`notifications`, `message`, `progress`, `loading`, `skeleton`, `empty`, `divider`, `label`
и др. — всего ~53) и барель `core/src/logos/index.ts`. Подключён `vite-plugin-svgr`:
импорт `./x.svg` даёт URL ассета, импорт `./x.svg?react` — React-компонент с инлайновым
`<svg>` (svgo отключён, чтобы Figma-эффекты — blur-фильтры, `foreignObject` — сохранялись
как есть). На каждый логотип барель экспортирует два имени: `<Name>` (компонент, принимает
пропы `<svg>`) и `<name>Url` (строка-URL для `<img>` / `background-image`).

Логотипы собираются во вторую точку входа `dist/logos.js` (см. `vite.config.ts`) и доступны
потребителям через подпуть `altrone-ui/logos` — в основной бандл `dist/index.js` не попадают.
В `package.json` добавлено поле `exports` с картами `.`, `./logos`, `./style.css` и
обратно-совместимым `./dist/*`. Типы для `./logos` синтезируются в standalone-вид
(`beforeWriteFile` в `dts()`), чтобы у потребителя не требовался свой `vite-plugin-svgr`.

Зачем: дать потребителям (docs и др.) фирменные логотипы компонентов — как инлайновый `<svg>`
для вёрстки, так и URL — не утягивая их в основной бандл.

## `Toast` → `Notifications` (переименование компонента)

Компонент-провайдер `Toast` переименован в `Notifications`, папка `core/src/components/toasts/`
→ `notifications/`, файлы `Toast.*` → `Notifications.*`, суб-компонент `ToastCard` → `NotificationCard`.
Публичный API: `Toast` → `Notifications`, `useToast()` → `useNotifications()`, тип
`ToastsProviderProps` → `NotificationsProviderProps`, `ToastPlacement` → `NotificationPlacement`
(используется и в пропах `AltroneApplication`). Локаль-ключ `toast` → `notifications` во всех
пяти словарях. Обновлён `mcp/docs/` (`Toasts.md` → `Notifications.md`).

Методы `toast()` и `notification()`, а также типы подтипа «пилюли» (`ToastOptions`,
`ToastVariant`, `ToastItem`, `ToastAction`) оставлены под прежними именами — «тост» это по-прежнему
один из двух режимов показа внутри провайдера, а переименование `Toast*` → `Notification*`
столкнулось бы с уже существующими `NotificationOptions`/`NotificationItem`/`NotificationAction`.

Зачем: `Notifications` точнее описывает компонент (он показывает и короткие тосты, и полноценные
карточки-уведомления); заодно у него появился логотип `notifications.svg`.

## Удалены компоненты `DataGrid` и `EntityList`

Из библиотеки убраны `DataGrid` (просмотр/редактирование одной записи по схеме `fields`) и
`EntityList` (вертикальный список структурированных элементов). Удалены папки
`core/src/components/dataGrid/` и `entityList/`, экспорты из `src/components/index.ts`, доки
`mcp/docs/DataGrid.md` / `EntityList.md`. Упоминания в сторис (`Box`, `Spacing`) и в rule-файлах
(`spacing.md`, `color.md`, `typography.md`, `rejected.md`) обновлены на живые компоненты.

Зачем: `EntityList` был крошечным (~125 строк), сырым и почти полностью повторялся композицией
`Flex`/`Box`/`Text`. `DataGrid` — schema-driven, что расходится с курсом v4 на композицию (см.
`rejected.md`), и тянул за собой большой roadmap. Оба не использовались ни в demo, ни в контенте
`docs`, тестов не имели. При необходимости вернём позже — уже в композиционном виде.

## Внутренние компоненты: `src/internal/`

Заведена папка `core/src/internal/` для компонентов, которые существуют только для композиции
внутри библиотеки и не входят в публичный API. Раскладка папки — как у `src/components/*`,
но без реэкспорта из `src/components/index.ts` и без `mcp/docs`. Импорт — `internal/<name>`
(через `baseUrl: ./src`); алиас `internal` добавлен в `.storybook/main.ts` и `vite.config.ts`.

Туда перенесён `badge` (`src/components/badge/` → `src/internal/badge/`). `Badge` и раньше не
экспортировался наружу и не был задокументирован — использовался только внутри `Dropdown`;
теперь это отражено расположением. `Badge exported: false` в собранном `dist/index.js`.

`CloseButton` рассматривался, но оставлен публичным: это тонкий, стабильный шорткат над `Button`
с локализованным `aria-label` и выключенным тултипом — переносить его = переложить a11y-грабли
на потребителя ради удаления страницы доков и трёх мелких демо.

Правило `components.md` дополнено разделом про `src/internal/`.

## Рефакторинг `Badge` + дедупликация бейджей

`internal/badge` переписан на `Box`: `shape="pill"`, `material` (`translucent` для `inline`,
`plate` для `corner`), `tone` (проп, по умолчанию `neutral`). Появились пропы `placement`
(`inline` | `corner`) и `size` (`mini`/`s`/`m`/`l`/`xl` — матрица высоты/`min-width`/паддинга/
шрифта, взята из `Button`). Старый битый `<div>` без цвета и тёмной темы убран; тема, контраст
и `ref` теперь идут от `Box`. Добавлена сторис `Internal/Badge`.

Инлайновые реализации бейджа удалены из `Button`, `Tabs.Item`, `NavigationList.Link`,
`BottomNavigation.Item` и `Dropdown.Action` — все рендерят `<Badge>`. Удалены переменные
`--*-badge-*` из `button/tabs/navigationList/bottomNavigation/dropdown` и соответствующие
`.Badge`-блоки (осталась только точечная подгонка отступов на стороне потребителя).

Публичный API не менялся: проп `badge` у Button/Tabs/NavigationList/BottomNavigation/Dropdown
принимает те же `string | number | ReactElement`, `Badge` по-прежнему не экспортируется наружу.

Правило `color.md` поправлено (у `Badge` теперь есть `tone` и заливка через `Box`).

## Убран `size` из `Dropdown`

Пункты меню всегда одной плотности. Проп `size` удалён из `Dropdown.Action`,
`Dropdown.Checkbox`, `Dropdown.RadioItem`, `Dropdown.ChildMenu` (и типов), вместе с тирами
`.Mini/.Small/.Large/.XLarge` в `action.module.scss` — остались фиксированные
`--dropdown-action-*` (высота 32px). Бейдж в `Dropdown.Action` тоже всегда одного размера
(дефолтный `m` у `Badge`).

Обновлены `mcp/docs/Dropdown.md`, `docs/content/ru/dropdown.md` (убраны проп и раздел
«Размеры») и сторис; демо `docs/demo/DropdownSizesDemo.tsx` удалено.

Зачем: выпадающее меню — это одна плотность строк; конфигурируемый размер добавлял API
и CSS-матрицу без реального сценария.

## Рефакторинг `CloseButton` + стори

`CloseButton` переписан на паттерн React 19: убраны `memo`, `ref` теперь принимается пропом и
пробрасывается в `Button` (нужно для `Tooltip`/`Popover` на кнопке закрытия). Три
identity-пропа (`icon`, `showLabel`, `tooltip`) применяются после спреда — их больше нельзя
перебить снаружи. `useLocalization` импортируется по файлу, а не из барреля `application`,
чтобы не замыкать цикл модулей.

Тип `CloseButtonProps` сужен: было `Omit<ButtonProps, 'label'>` (наружу торчал весь `Button` —
`variant`, `badge`, `state`, `additionalIcon`…), стало курируемый набор — `size`, `asChild`,
`label` (переопределение доступного имени) + нативные атрибуты `<button>` кроме `aria-label`.

Добавлена `CloseButton.stories.tsx` (`Components/Atoms/CloseButton`) — обзор с живым
закрытием карточки, размеры, шапки панелей, доступное имя и `disabled`. Удалён `REFACTORING.md`.

Ломающее: код, передававший `CloseButton` пропы `Button` вне нового набора, теперь не
типизируется.

## `Empty` → `Result` (расширение до фидбек-компонента)

Компонент `Empty` переименован в `Result` и обобщён под разный фидбек — по образцу
`Result` из antd. Папка `core/src/components/empty/` → `result/`, файлы `Empty.*` → `Result.*`,
`--empty-*` → `--result-*`.

Новый проп `status`: `'empty'` (по умолчанию, нейтральное «нет данных» — прежнее поведение),
`'info'`, `'success'`, `'warning'`, `'error'`. `status` задаёт дефолтную иконку и тонировку
медиа-чипа (семантическими role-токенами из `color.md`; текст остаётся нейтральным).
`status="error"` рендерит `role="alert"`, остальные — `role="status"`. Проп `icon`
переопределяет иконку статуса.

Пропы `title` / `description` / `actions` / `size` / `children` без изменений (в т.ч.
поведение «одиночная строка становится заголовком»). Локаль-ключ `empty.noData` →
`result.empty` во всех пяти словарях.

Потребители переведены: `AutocompleteInput`, `DataTable` (пустая таблица и «нет фильтров»).
Обновлены `mcp/docs/` (`Empty.md` → `Result.md`, ссылки в `Screen.md`) и
`docs/content/ru/screen.md`.

Ломающее: `import { Empty }` → `import { Result }`; ключ локализации переименован.
