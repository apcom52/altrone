## Рефакторинг Dialogs (`showAlert` / `showConfirm` / `showPrompt`)

Императивный API диалогов и `DialogProvider` приведены в порядок по заметкам
рефакторинга.

Что изменилось:

- **Локализация**. Все дефолтные строки (`OK` / `Confirm` / `Cancel`, заголовки
  `Alert` / `Confirm` / `Prompt`, плейсхолдер prompt) больше не захардкожены —
  `DialogProvider` берёт их из `useLocalization()`. Добавлен блок `dialog.*`
  во все пять словарей (`en` / `ru` / `fr` / `ge` / `sp`).
- **`options` теперь обязателен** у `showAlert` и `showConfirm` (у `showPrompt`
  уже был). Раньше `showAlert()` / `showConfirm()` без аргументов открывали
  диалог с пустыми строками. Убраны внутренние `options || {}`.
- **Стек обработчиков вместо глобального синглтона**. `registerDialogHandler` /
  `unregisterDialogHandler(handler)` работают со стеком: вложенные
  `DialogProvider` и тесты, монтирующие свой провайдер, больше не затирают друг
  друга, а размонтирование возвращает управление предыдущему провайдеру.
  `unregisterDialogHandler` теперь принимает сам обработчик.
- **`DialogProvider`**: `inputValue` типизирован как `string | number | null`
  (был `unknown` с приведениями); разнородный `handleConfirm(result)` разбит на
  `accept` / `cancel` по типу диалога; убран мёртвый негативный
  `margin-bottom: -12px` у контента.
- **Публичный экспорт**: `DialogProvider` и типы `AlertOptions` /
  `ConfirmOptions` / `PromptOptions` / `PromptType` теперь реэкспортируются из
  `components/dialog` (раньше `DialogProvider` был доступен только через
  `AltroneApplication`).
- Сторис переписаны как документация-статья: обзор с await-сценарием
  (confirm → работа → alert), отдельные разделы Alert / Confirm / Prompt с
  живым выводом результата.

## Modal: `children` (триггер) стал необязательным

`Modal` больше не требует элемент-триггер. Без `children` он работает как
полностью управляемый (`openedByDefault` + `onClose`) и не рендерит триггер.

Зачем: `DialogProvider` раньше передавал в `Modal` фиктивный `<div />` только
чтобы удовлетворить обязательный `children` и сразу открывал модалку через
`openedByDefault` — теперь этот хак не нужен.

## Рефакторинг Message

Компонент `Message` приведён к целевому паттерну v4 по заметкам рефакторинга.

Что изменилось:

- **React 19 паттерн**: убраны `memo` и обёртка — теперь это обычная функция,
  `ref` принимается как обычный проп и прокидывается в корневой элемент.
- **`ariaRole` по умолчанию зависит от `severity`**. Раньше корень всегда
  получал `role="alert"` — скринридер ассертивно прерывался на любом, даже
  чисто информационном, сообщении. Теперь `alert` только при
  `severity="danger"`, для остальных — вежливый `role="status"`. Явный
  `ariaRole` по-прежнему переопределяет это.
- **Корень — примитив `Box`** (`material="glass"`, `shape="rounded"`).
  `severity` мапится на `tone` Box (`primary → accent`,
  `success`/`warning`/`danger` — одноимённо, без severity → `neutral`).
  Собственный skin Message ушёл: удалены `--message-background-color` /
  `--message-border-color` / `--message-accent-text-color` и классы
  `Role*`/`Severity*` — цвет фона, тинты и цвет заголовка/иконки теперь берутся
  из `--box-tone-*`. `message.module.scss` держит только раскладку баннера
  (Box по умолчанию — центрированный inline-flex контрол) и типографику частей.
- **Дизайн изменился**: убран левый акцентный бордер, радиус стал симметричным
  (было `0 24 24 0`), фон — полупрозрачный frosted-тинт (`glass`, с
  `backdrop-filter`) вместо плотной плашки. Сделано ради консистентности с
  остальными компонентами на `Box`.
- **Отступы зависят от иконки**: без `icon` горизонтальный `padding` Box
  увеличивается (`{ x: 16, y: 8 }` против `8`), чтобы текст не прилипал к
  скруглённому краю на месте иконки.
- **Кнопка закрытия остаётся круглой**: корень выровнен по `flex-start`
  (`CloseButton` больше не растягивается по высоте баннера).
- **`renderFunc` удалён** — для сообщений подмена корневого элемента избыточна;
  вместе с ним убран тип `MessageRenderProps`. Полиморфизм — задача `Box`
  (у которого его сознательно нет, только `asChild`), Message его не пробрасывает.
- **Удалён устаревший проп `role`** (был deprecated → `severity`). Вместе с ним
  ушли `GlobalUtils.deprecatedMessage`-проверка и `useEffect` под неё.
- **Типы**: `MessageProps` теперь `Omit<HTMLAttributes, 'role'>` (единственный
  способ задать роль корня — `ariaRole`); `header` — `ReactNode`,
  `actions`/`icon` — `ReactElement` вместо устаревшего алиаса `JSX.Element`.
- Сторис переписаны как документация-статья: обзор, разделы Severities /
  Without an icon / Dismissible / With actions / Compact / Accessibility.
  Unit-тесты переписаны под новый API (дефолт `ariaRole`, close button).

Зачем: убрать legacy-обвязку (`memo`, `useEffect`, deprecated-проп, ручной
skin) и посадить Message на общий примитив `Box`, чтобы материалы, тона,
радиусы и elevation были такими же, как у остальных компонентов v4; заодно
исправлено агрессивное `role="alert"` по умолчанию как проблема доступности.

## Рефакторинг Progress

Компонент `Progress` приведён к целевому паттерну v4 по заметкам рефакторинга.

Что изменилось:

- **React 19 паттерн**: убран `memo` — обычная функция, `ref` как обычный проп.
- **Новый проп `min`** (по умолчанию `0`). Доля заливки теперь считается по
  диапазону — `(value - min) / (max - min)` — и `aria-valuemin` больше не
  захардкожен нулём. `ProgressContext` (аргумент render-функции лейбла) получил
  поле `min`.
- **Клампинг ARIA**: `aria-valuenow` зажимается в `[min, max]`, деление на ноль
  при `min === max` защищено (`span || 1`). Значение вне диапазона рисует
  корректную полосу и валидные ARIA-атрибуты.
- **Доступное имя**: строковый `children` дублируется в `aria-label` (если
  потребитель не задал свой). Нестроковый лейбл имени не даёт — задокументировано,
  что рядом нужен `aria-label`.
- **`size`**: раньше в стилях жили только `s`/`l` (`mini`/`xl` молча
  отображались как `m`). Добавлены `.Mini` и `.XLarge` — полная шкала
  `mini/s/m/l/xl` действительно работает (высота полосы + типографика лейбла).
- **`value`/`max` стали необязательными** в типах (дефолты `0`/`100` и так были
  в компоненте — тип это отражал неверно, помечая их required).
- **Типы**: `children` теперь `ReactNode | ((ctx) => ReactNode)` вместо
  `string | ReactElement | ((ctx) => ReactElement)` — render-функция лейбла
  может вернуть строку (в сторис так и делалось, но тип это запрещал). Импорт
  через алиас `types`, без `React.`-нэймспейса.
- **Трек — примитив `Box`** (`shape="pill"`, `material="glass"`,
  `tone="neutral"`). Box отвечает за пилюльный радиус (из общей шкалы) и за
  фон трека (свой нейтральный frosted `glass`-fill с `backdrop-filter`).
  Собственная переменная `--progress-background-color` удалена; активная
  заливка и текст остаются своими (`--progress-active-background-color`,
  `--progress-text-color`), при этом дефолт активной заливки стал ярче —
  `--accent-9` вместо `--accent-6`.
  `progress.module.scss` перебивает центрирующий inline-flex Box на full-width
  полосу (компаунд `.Progress.Progress`).
- **CSS**: геометрия вынесена в компонентные переменные
  (`--progress-height`, `--progress-padding-inline`); хардкод `border-radius: 16px`
  и `background-color` трека убраны (даёт Box); `z-index: 1` у лейбла
  прокомментирован (перекрывает абсолютную заливку).
- Сторис переписаны как документация-статья: Overview / Sizes / Labels /
  Value range / Live value (управление через `Range`) / Theming. Unit-тесты
  переписаны под новый API (min, клампинг, `min === max`, `aria-label`);
  выпилен нерабочий тест на `useConfiguration` (Progress его не читает).

Зачем: закрыть баги доступности (ложный `aria-valuemin`, `aria-valuenow` вне
диапазона, отсутствие имени у progressbar), сделать шкалу `size` честной и
убрать legacy-обвязку.

## Рефакторинг Tags

Компонент `Tags` приведён к целевому паттерну v4 по заметкам рефакторинга.

Что изменилось:

по-настоящему инертное поведение, а кликабельным — корректную клавиатуру, и

## Рефакторинг Toast / Notifications

Императивная система тостов и уведомлений (`useToast()` → `toast` /
`notification` / `dismiss`) приведена к целевому паттерну v4, очищена от
незавершённой миграции с `sonner`, а позиционирование вынесено из вызова в
глобальную настройку.

Что изменилось:

- **Одна реализация вместо двух под-компонентов.** `ToastMessage` и
  `Notification` слиты в один внутренний компонент `ToastCard`, который по
  `item.kind` рисует либо тост-пилюлю, либо карточку уведомления. Общими стали
  поверхность, таймер авто-закрытия, пауза по наведению и пружинная
  анимация появления/исчезновения.
- **Никакой сторонней зависимости.** Анимация целиком на `motion` (spring
  вход + `easeIn` выход). Остатки `sonner` / `react-toastify` и мёртвая папка
  `inner/` со старыми компонентами удалены.
- **Карточка — примитив `Box`** (`material="plate"`, `elevation="toast"`).
  Тост — `<Box shape="pill" …>`, уведомление — `<Box radius={20} …>`. Свой
  скин ушёл: удалены `--toast-background-color` / `--toast-border-color` /
  `--toast-border-radius` / `--notification-border-radius`, класс `.Wrapper` и
  дублирующийся `color`. Радиус, hairline и тень — из `Box`. Заливка `plate`
  frosted-полупрозрачная, а карточки висят над контентом без затемняющего
  скрима, поэтому `--box-fill` переопределён на непрозрачный `--toast-surface`
  (`--gray-1`, авто-тема) — фон больше не просвечивает.
- **Позиционирование стало глобальным (breaking).** Проп `position` убран у
  `toast()` и у `notification()` (вместе с типом `ToastItemPosition`). Вместо
  него — три пропа на `<AltroneApplication>` (проксируются во внутренний
  `<Toast>`): `toastPlacement`, `notificationSide`, `notificationPlacement`,
  каждый `'start' | 'end'` (логические, дефолт `'end'`). Для вертикали
  `start` = верх, `end` = низ; для `notificationSide` `start` = слева,
  `end` = справа. Тост всегда центрируется по горизонтали. Новый тип
  `ToastPlacement` в публичном экспорте вместо `ToastItemPosition`.
- **Два стека вместо шести.** Раньше было по контейнеру на каждую из шести
  позиций; теперь ровно один стек тостов и один стек уведомлений,
  позиционируемые глобальными пропами.
- **Анимации.** Два вложенных враппера: внешний `.Slot` несёт `layout` (при
  добавлении/удалении карточки остальной стек плавно едет на новое место, а
  не прыгает), внутренний `.Item` — enter/exit-трансформ (держится отдельно
  от `layout`-ноды). Пружины смягчены и сделаны «живее»: вход — `spring`
  240/22/0.9 с лёгким overshoot, вылет — быстрый 16 ms `easeIn`, reflow —
  критично задемпфированный `spring` 340/36 без раскачки; дистанция входа
  увеличена (тост ±28 px по вертикали, уведомление ±36 px от края).
- **`Button`: убран `layout` с корневого `<motion.button>`** (осталась только
  анимация ширины у внутренних `ButtonContent`/`ButtonLabel`/`ButtonIcon`).
  `layout`-проекция корня кнопки контр-масштабировала себя против трансформа
  анимирующегося предка — из-за этого кнопки внутри тоста/уведомления не
  участвовали во входной анимации карточки. Побочный эффект: смена ширины
  кнопки при смене контента (label/иконка/`state`) теперь мгновенная, а не
  плавная.
- **React 19 паттерн**: `Toast`-провайдер — обычная функция без `memo`.
- **Доступность**: portal-root получил `role="region"` +
  `aria-label={t('toast.regionLabel')}` (новый ключ `toast.regionLabel` во
  всех пяти словарях), сохранён `aria-live="polite"`.
- **Отступы** переведены на семантические токены (`--space-content` /
  `--space-stack` / `--space-inline`) вместо хардкод-px; битые
  `--toastTextColor` / `justify-self: flex-end` / `background: white` из
  старого кода удалены вместе с их файлами.
- Сторис пока сведены к одной — `Testing — all cases` (режимы, варианты,
  состояния иконки, экшены, персистентность, пауза по наведению, стек,
  программный `dismiss`). Витринные истории добавим позже.
- Удалён `REFACTORING.md` — заметки отработаны.

Зачем: дожать миграцию с `sonner`, свести тосты и сложные уведомления в один
компонент на общем примитиве `Box`, упростить модель позиционирования (одна
глобальная настройка вместо параметра на каждый вызов) и починить анимацию
появления кнопок.

## Рефакторинг Grid

Контейнер `Grid` и `Grid.Column` приведены к целевому паттерну v4 по заметкам
рефакторинга.

Что изменилось:

- **React 19 паттерн**: убран `memo` из `Grid` и `Grid.Column` — обычные
  функции, `ref` как обычный проп прокидывается в корневой элемент. `Grid`

- **Новый проп `tagName`** (по умолчанию `'div'`) у `Grid` и `Grid.Column` —
  как у `Flex`. Сетку можно отрендерить как `<ul>`/`<section>`, а колонки —

- **Исправлена математика ширины колонки.** Формула не учитывала гэпы,
  попадающие внутрь спана: `size={6}` был уже, чем реально нужно, на
  `(size − 1) × gap`, поэтому у ряда из k колонок правый край не дотягивал

  колонка добавляет `(size − 1) × gap` к своей доле, `offset` — симметрично;
  любой ряд с суммой `size` = 12 заполняет ширину ровно.
- **CSS-переменные переименованы под компонент** (`theming.md`):
  `--column-spacing`/`--row-spacing` → `--grid-column-spacing`/`--grid-row-spacing`,
  `--column-size`/`--column-offset` → `--grid-column-size`/`--grid-column-offset`.
- **`offset={0}` больше не пишет `--grid-column-offset`**, а `size="auto"` —
  `--grid-column-size`: переменная ставится только когда действительно влияет
  на раскладку (раньше `--column-offset: 0` выставлялся впустую).
- **Типы**: `GridProps`/`GridColumnProps` — на `HTMLAttributes<HTMLElement>`
  (было `HTMLProps`), импорты без `React.`-нэймспейса; экспортированы
  `GridColumnSize` и `GridColumnOffset`.
- Сторис переписаны как документация-статья: Overview / Column sizes /
  Auto columns / Gap and row gap / Offsets / No wrap / Custom element /
  Real-world layout. Unit-тесты переписаны под фактическое поведение
  (маппинг `gap`, `--grid-column-size`/`--grid-column-offset`, `tagName`,
  проброс `ref`); выпилен нерабочий тест на `Configuration` (`Grid` его
  не читает, и сам `Configuration` больше не экспортируется).
- Удалён `REFACTORING.md` — заметки отработаны.

Зачем: снять legacy-обвязку (`memo`, `HTMLProps`, неконсистентные имена
CSS-переменных), дать `Grid` тот же полиморфизм по `tagName`, что и у `Flex`,
и убрать мёртвую запись CSS-переменных при нейтральных значениях пропов.

Контейнер `Flex` приведён к целевому паттерну v4 по заметкам рефакторинга.

Что изменилось:

- **React 19 паттерн**: убран `memo` — обычная функция, `ref` как обычный
