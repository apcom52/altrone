## Рефакторинг Calendar: полноценный компонент + два уровня API

`Calendar` переписан. Раньше это была почти без стилей сетка дней с единственным
низкоуровневым API (`selectedDates` + `DateComponent`), причём заявленный проп
`firstDayOfWeek` не был реализован, а последняя неделя месяца обрезалась.

Что изменилось:

- **Высокоуровневый API**: проп `mode` (`single` / `multiple` / `range`) с
  собственным состоянием выбора (`value` / `defaultValue` / `onSelect`), шапкой с
  навигацией по месяцам (`month` / `defaultMonth` / `onMonthChange`) и строкой
  дней недели.
- **Подсветка диапазона** в `mode="range"` с предпросмотром полосы при
  наведении — та же логика, что в `DatePicker.Range`. Полоса — сплошной блок,
  скругляются только её внешние углы (радиусом кружка выбранного дня); в местах
  переноса на следующую неделю углы прямые. `CalendarRenderDateProps` получил
  `inRangeAbove` / `inRangeBelow` для этого расчёта.
- **Локали и первый день недели**: подпись месяца и названия дней берутся из
  `Intl` по активной локали (или пропу `locale`). `firstDayOfWeek` теперь
  реально работает и по умолчанию `'auto'` — воскресенье для `en-US`,
  понедельник для `ru-RU` и т.д.
- Фиксированная сетка 6×7 (высота не скачет), пропы `minDate` / `maxDate` /
  `isDateDisabled`, `showHeader` / `showNavigation` / `showWeekdays` /
  `showOutsideDays`, `ref` пробрасывается на корень.
- Оформление максимально приближено к календарю внутри `DatePicker`: ячейка
  32px, hover/selected «пилюля» (`--interactive-a1` / стеклянный фон с
  `--elevation-raised-shadow`), выходные и «сегодня» акцентным цветом. Всё на
  дизайн-токенах (`--calendar-*` поверх `--accent-*` / `--text-*` /
  `--interactive-*`), тёмная тема без отдельного блока.
- «Пилюля» выбранного дня анимируется через `motion` (`motion/react`):
  scale-in с лёгким пружинным баунсом при появлении, scale-out при исчезании.
  Reduced-motion уже покрыт `MotionConfig` в `AltroneApplication`.
- Низкоуровневый API (`selectedDates` / `cursorDate` / `onDateChange` /
  `DateComponent`) сохранён без изменений — шапка и дни недели при нём по
  умолчанию скрыты, корень остаётся плоской сеткой кнопок. `DatePicker` не
  затронут.
- `CalendarDate` переехал в `calendar/components/`, экспортируется как
  `Calendar.Date`. Добавлены ключи локализации `calendar.previousMonth` /
  `calendar.nextMonth` во все пять словарей.

Зачем: `Calendar` должен быть самостоятельным компонентом с приятным
оформлением и понятным API для прямого использования, а не только скрытым
строительным блоком `DatePicker`. Локале-зависимый старт недели — базовое
требование к календарю.

## Рефакторинг DatePicker: day-вью на новом Calendar

Дневная сетка `DatePicker` / `DatePicker.RangePicker` больше не переопределяет
всё вручную — она рендерит `<Calendar mode="single" | "range">` из библиотеки.

Что изменилось:

- Удалены `DayButton.tsx` (~155 строк, своя реализация hover/selected/подсветки
  диапазона, причём цветовой токен полосы был мёртвый), `day.module.scss`,
  `inner/mixins.scss` (мёртвые `--datePickerDay*` переменные), мёртвый
  `useKeyboardSupport.ts`, ручная строка дней недели (`weekdaysMin`, ломала
  локаль).
- `DayPicker.tsx` теперь тонкая обёртка: `<Calendar>` внутри `Composite`
  (roving tabindex сохранён), ячейка — `Calendar.Date`, обёрнутая в
  `CompositeItem`. Подсветка диапазона, анимация «пилюли», скругление углов
  полосы, дни недели и старт недели по локали — всё из `Calendar`.
- `Calendar.Date` теперь принимает и прокидывает `ref` и произвольные
  атрибуты кнопки — чтобы её можно было оборачивать (`CompositeItem`).
- Диапазон: `RangePicker` отдаёт `{ from, to }` из `Calendar` через новый
  `onRangeChange` в контексте; `minDate` / `maxDate` теперь реально работают
  для диапазона (раньше игнорировались).
- Из контекста убраны нереализованные `hoveredDate` / `setHoveredDate` —
  hover-состояние диапазона теперь внутри `Calendar`.
- `MonthPicker` / `YearPicker` (внутренние вью) переписаны на общий компонент
  `PickerCell` — то же визуальное решение, что у `Calendar.Date`: CSS-подложка
  на `:hover` + анимированная «пилюля» выбранного (`motion/react`, scale-bounce).
  Убраны «плавающая» подложка на `layoutId`, состояние `mouseOver*`,
  `framer-motion`, мёртвый `DatePickerIdContext`. Ячейки месяца/года теперь
  pill-формы, во всю ширину колонки, текст по центру.
- **Фиксы поповера месяца/года**:
  - Схлопывался по ширине (сетки `width: 100%`, а поповер без дневной сетки не
    имел базовой ширины). Контент поповера зафиксирован на ширине дневной сетки
    (`var(--calendar-width)`), заголовок не переносится (`white-space: nowrap`).
  - Отключённые (вне `minDate`/`maxDate`) месяцы/годы визуально не отличались от
    активных — казалось, что «ничего не кликается». Теперь у них приглушённый
    цвет и нет hover-подложки (класс `.Disabled`, как в `Calendar.Date`).
  - Пустой футер (когда нет кнопок «Очистить» / «Сегодня») больше не рендерится.
- Почищены мёртвые CSS-переменные и селекторы в `datePicker.module.scss` /
  `header.module.scss`.
- Публичный API `DatePicker` не изменился (`value` / `onChange` / `clearable`
  / `format` / `minDate` / `maxDate` / `autoClose` / `readOnly`).
- Сторибук `Calendar` и `DatePicker` переписаны как связные сценарии
  («Cedar Cabin» — бронирование домика; «Kestrel» — заказ чартера). Попутно
  убраны устаревшие `Grid.Column`/`transparent` из историй `DatePicker` —
  теперь оба файла проходят `tsc` без ошибок.

Зачем: убрать дублирование между `DatePicker` и `Calendar` — одна реализация
дневной сетки, один набор стилей, одно место для правок.

## Рефакторинг ColorPicker

Почищена внутренняя реализация `ColorPicker` без изменения формы публичного API.

Что изменилось:

- Добавлен проп `renderFunc?: (ctx) => ReactElement` (как у `Select` /
  `DatePicker`): полностью заменяет дефолтный `TextInput`-триггер, в `ctx`
  приходят `value` / `opened` / `disabled` / `placeholder` / `className` /
  `style`. Экспортирован тип `ColorPickerRenderProps`.
- `onChange` теперь действительно получает DOM-событие вторым аргументом (тип
  это уже декларировал, но обёртка внутри его роняла) — при выборе из пресета
  и при вводе hex в поповере событие пробрасывается наружу.
- `size` пробрасывается в поповер: hex- и RGB-поля внутри теперь совпадают по
  размеру с триггером. Диаметр кружка-превью пересчитан по тирам (`mini` 10,
  `s` 16, `m` 20, `l` 28, `xl` 32) — раньше на `mini`/`s` он был почти во всю
  высоту поля.
- Внутреннее состояние `ColorPickerContent` свёрнуто: вместо трёх `useState` +
  трёх `useEffect`, синхронизировавших `localColor`/`red`/`green`/`blue` с
  `value`, теперь один `useEffect` на `value` и чистые хелперы
  `parseChannels` / `toHexByte` для конвертации hex↔RGB. Убраны мёртвые
  зависимости в колбэках и лишний вложенный `Flex`.
- Исправлена подсветка выбранного пресета: сравнение `preset.value === value`
  было регистрозависимым, а `value` всегда приводится к нижнему регистру —
  пресеты с hex в верхнем регистре никогда не подсвечивались (галочка не
  появлялась). Теперь сравнение регистронезависимое.
- Поля hex / R / G / B в поповере больше не вылезают за его границы: hex занял
  отдельную строку на всю ширину, R/G/B — тремя равными колонками ниже
  (`min-width: 0`), потому что `className`/`style` у `TextInput`/`NumberInput`
  уходят на внутренний `<input>`, а не на flex-обёртку.
- `ColorPreset`: `box-shadow` рамки переведён с захардкоженного `rgba(0,0,0,.2)`
  на `var(--border-a2)` (как у превью цвета), `:focus` → `:focus-visible`,
  удалено мёртвое правило.
- Галочка выбранного пресета теперь рисуется общим `CheckIcon` из `checkbox`
  (тот же, что в `Checkbox` / `Dropdown.Checkbox`) — с прорисовкой линии по
  `stroke-dasharray` при появлении, вместо статичной иконки `lucide`.
- Кружок пресета при клике проигрывает короткий bounce (`scale`
  1 → 0.85 → 1.08 → 1) через `motion/react`. Reduced-motion покрыт
  `MotionConfig` в `AltroneApplication`.
- Удалён неиспользуемый класс `.InputLabel` (на легаси-переменных
  `--labelFontSize` и т.п.). `!important` на `.Palette` оставлен с
  комментарием — он гасит рантайм-стиль `react-colorful`.
- Сторибук переписан: шесть самостоятельных сценариев вместо одной сборной
  истории — Gradient Forge (сборка `linear-gradient`), Neon Sign Studio
  (glow через `text-shadow`), Building a palette (редактор токенов с живым
  превью), Writing desk (тулбар форматирования на `asChild`), и справочные
  «Three ways to pick» / «Sizes, states & custom triggers».

Зачем: реализация обросла дублирующей логикой конвертации цвета и лишними
ре-рендерами; сторис демонстрировали API, а не показывали, зачем компонент
нужен.

## DatePicker: сменный контрол (`renderFunc` / `asChild`)

По аналогии с `Select`, `DatePicker` (и `MonthPicker` / `YearPicker` /
`RangePicker`) теперь позволяет заменить дефолтный `TextInput`-триггер:

- `renderFunc?: (ctx) => ReactElement` — возвращённый элемент становится
  триггером; `ctx` содержит `value`, `displayValue`, `expanded`, `disabled`,
  `clear`, а также `className` / `style` пикера.
- `asChild?: boolean` + `children?: ReactElement` — свой элемент как триггер,
  props пикера домёржатся через `Slot`.
- `useDatePickerTrigger()` — хук для чтения того же live-состояния из
  вложенного компонента (экспортирован из публичного API).

Добавлена история `Custom trigger — renderFunc & asChild` с примерами (кнопка,
инлайн-триггер, `asChild`, компонент на `useDatePickerTrigger()`).

Зачем: не заставлять потребителя мириться с полем ввода там, где триггером
должна быть кнопка, чип или произвольный элемент.

## Рефакторинг Range: два варианта, читаемость, чистка

`Range` разделён на два визуальных варианта через новый проп
`variant` (`'default'` | `'fill'`, по умолчанию `'default'`).

Что изменилось:

- **`variant="default"`** — обычный слайдер: тонкая дорожка (`--radius-pill`) +
  ползунок с материалом `plate` (как у `Box`: матовая заливка, слоистая
  hairline-тень); в тёмной теме кружок получает белую заливку, как у нативного
  ползунка macOS/iOS и как submit-кнопка. При нажатии и перетаскивании кружок
  вытягивается в короткую пилюлю (радиус фиксирован в половину высоты, так что
  форма меняется только шириной, без скачка). Фокус — кольцо вокруг кружка
  (у `fill` — вокруг всего слэба), стандартный `outline` снят. Это новый дефолт.
- **`variant="fill"`** — прежний вид «плашки» из Control Center iOS
  (стеклянный фон, заливка во всю высоту, значение и иконка внутри). Вынесен в
  отдельный вариант, потому что подходит не под все кейсы.
- **Читаемость**. Активная заливка теперь `--accent-9` (сплошной акцент) вместо
  почти невидимого `--accent-3` поверх `--interactive-a1`. Текущее значение в
  `default` — плашка со сплошным фоном (`--text-2` / `--background-1`) над
  ползунком; в `fill` — матовая translucent-пилюля (`--interactive-a3` +
  `--glass-effects`), как бейдж у `Button`. `mix-blend-mode: luminosity` убран.
- `size` принимает всю шкалу `mini/s/m/l/xl` (раньше де-факто `s/m/l`, причём
  `.Large` дублировал дефолтную высоту). Размер задаёт толщину дорожки, диаметр
  ползунка и высоту плашки `fill`.
- `fill` при нажатии не увеличивается (был scale на `framer-motion`), а слегка
  притемняется (`filter: brightness(0.96)`). Зависимость `framer-motion` из
  компонента убрана; все переходы — на `--motion-duration-*` (reduced-motion
  бесплатно).
- Исправлена вертикальная ориентация `fill`: правило `.Vertical .Track`
  перебивало абсолютное позиционирование дорожки слэба, и заливка схлопывалась
  в узкую полосу вместо всей ширины.
- Чистка: удалён мёртвый класс `.Input` (`overflow: 0`), `@include`-и на
  легаси-переменных типа `--paragraphFontSize` заменены на `--text-size-*`,
  `memo` убран (`ref` уже был обычным пропом).
- Сторис переписаны как связные сценарии (по образцу `ColorPicker` /
  `DatePicker`): Darkroom (панель фотокоррекции на `default`-слайдерах,
  `renderLabel` со знаком, `onValueCommit` для «тяжёлого» пересчёта),
  Mixing Desk (вертикальные `fill`-фейдеры каналов + `default` для панорамы),
  Now Playing (скраббер `default` + громкость `fill` в одной карточке),
  Thermostat (один крупный вертикальный `fill`, шаг `0.5`), Anatomy & options
  (оба варианта, шкала размеров, состояния, клавиатура).

Зачем: «плашка» Control Center выразительная, но тяжёлая для плотных форм —
нужен и привычный слайдер; и в обоих случаях текущее значение должно быть
видно.

## Рефакторинг DataTable: тонкая обёртка над TanStack Table v9

`@tanstack/react-table` обновлён с v8 на v9 (крупный рекан API), а `DataTable`
переписан так, чтобы вся табличная логика жила в экземпляре TanStack Table, а
компонент оставался только обёрткой над ним.

Что изменилось:

- **Ядро на v9**: `useReactTable` + `get*RowModel()` заменены на `useTable` с
  явным набором фич (`tableFeatures({ columnFilteringFeature, rowSortingFeature,
  rowPaginationFeature, rowSelectionFeature, columnResizingFeature, … }`) в
  отдельном модуле `DataTable.features.ts`. `mode` и конфиг колонки уезжают в
  типобезопасные `tableMeta` / `columnMeta`, а не в самопальные поля состояния.
- **Убран хак с `selectableMode`**: режим выбора строк раньше подмешивался в
  состояние TanStack через `table.setState`. Теперь это обычный React-state в
  обёртке (`selectable` включает фичу и тумблер в шапке; `mode="select"` задаёт
  стартовое значение), прокинутый через контекст `{ table, loading, selectable,
  selectMode, setSelectMode }`.
- **Новый публичный API фильтров**. Большой discriminated union `Filter`
  (`conditions[]`, `join: 'AND' | 'OR'`) удалён — UI всё равно использовал одно
  условие и всегда AND, а `defaultFilters` не совпадал по форме с формой
  фильтра. Вместо него `DataTableFilter = { id, value: { rule, value?, level? } }`
  — та же форма, что у нативного `columnFilters`. `defaultFilters` кладётся
  прямо в `initialState`, `onFilterChange` всегда отдаёт массив (пустой —
  когда фильтров нет). `FilterType` больше не экспортируется; экспорт enum-ов
  правил (`StringFilterRules` и т.д.) сохранён.
- **Ресайз колонок**: новый проп `resizableColumns` (по умолчанию `false`) и
  per-column `resizable` — тянется за правый край заголовка.
- **Проброс `ref`** на корневой `div`; `motion.div`-обёртки без анимации
  заменены на `div`; `children` в шапку передаётся как JSX-дети, а не проп;
  `console.log`/`console.warn` в `numberFilterFn` убраны; починен off-by-one в
  пагинации футера; `linkRenderer` больше не выводит `undefined` при пустом
  трансформере.
- Локализация: строки шапки/пустого состояния/выбора правила больше не
  захардкожены — добавлены ключи `dataTable.empty`, `dataTable.chooseRule`,
  `dataTable.selectFilter.*`, `dataTable.colorFilter.*`,
  `dataTable.passwordFilter.*` (последние три раньше просто отсутствовали, хотя
  на них ссылались константы), `datePicker.startDate` / `datePicker.endDate` —
  во все пять словарей.
- Удалены мёртвые файлы (`DataTableCell.tsx`, `useVisibleColumns.ts`,
  `DataTableFilter.types.ts`, `REFACTORING.md`, случайный `typo.png`).
- Сторис полностью переписаны как связная документация-статья по фичам
  (типы колонок и рендереры, сортировка, фильтрация, пагинация, выбор строк,
  тулбар и row actions, loading-режим, ресайз колонок, серверные колбэки,
  пустое состояние). Unit- и Cypress-тесты переписаны под новый API и
  div-grid-разметку; строковые фильтр-функции покрыты граничными кейсами.
- `mcp/docs/DataTable.md` обновлён (форма `DataTableFilter`, `resizableColumns`,
  `resizable`, удаление `Filter`).
- Доводка по фидбеку: фильтр по диапазону дат (day-уровень) теперь один
  `DatePicker.RangePicker` вместо двух полей; строка фильтра всегда 4 колонки
  (`165px 135px 1fr 32px`) — кнопка удаления больше не «плавает» между
  вариантами с 1 и 2 полями значения. У тулбар-шапки убраны фон-заливка и
  нижний внутренний отступ (`padding-bottom: 0`). Разделитель-ресайзер
  заголовков переведён на визуальный язык `Splitter` (пилюля-handle на
  `--splitter-handle-*`); handle укорочен (16px), показывается только при
  наведении на заголовок, анимация появления/увеличения и active-bump — через
  `motion` (variant-propagation с ячейки заголовка, reduced-motion бесплатно
  из `MotionConfig`). Счётчик в футере («N rows shown») считает реально
  отрисованные строки текущей страницы, а не `rowsPerPage` — на последней
  неполной странице цифра больше не завышалась.

Зачем: `DataTable` — самый тяжёлый компонент библиотеки, и половина его кода
дублировала то, что TanStack Table уже умеет, местами борясь с ним
(`setState` для кастомного поля, ручной трекинг состояния через эффекты).
Перенос логики в ядро уменьшает поверхность для багов, а v9 даёт более чистую
базу под обёртку.

## Рефакторинг Modal: React 19, исправление багов закрытия и a11y

`Modal` переписан на паттерн React 19 (без `forwardRef` / `memo`), публичная
форма пропов не изменилась.

Что изменилось:

- **Двойной вызов `onClose`** убран: `AnimatePresence` теперь оборачивает
  условный рендер (`{opened && …}`), проп `onExitComplete` удалён — обработчик
  закрытия вызывается ровно один раз (по Escape, клику по фону или кнопке).
- **Escape-обработчик** больше не страдает от stale closure: слушатель
  объявлен внутри `useEffect`, `handleClose` обёрнут в `useCallback`,
  зависимости эффекта корректны.
- **A11y**: `role="dialog"` и `aria-modal="true"` теперь на одном элементе
  (панель `.ModalContent`, а не внешний backdrop); `aria-labelledby`
  проставляется только при наличии `title`.
- **Закрытие по клику на подложку** срабатывает только на прямой клик по ней
  (`event.target === event.currentTarget`), а не по DOM-проверке
  `closest('[aria-modal]')` — иначе выбор опции в `Select` (меню рендерится в
  портал вне `.ModalContent`) закрывал модалку.
- **SSR**: доступ к `document` для портала убран из рендера за гвард
  `typeof window`.
- `FocusTrap` теперь рендерится внутри портала (раньше оборачивал
  `AnimatePresence` снаружи `createPortal`); включён `allowOutsideClick`, иначе
  ловушка фокуса гасила клик по подложке и модалка не закрывалась по нему.
- `ref` — обычный проп, пробрасывается на корневой элемент; собственный
  `onClick` элемента-триггера сохраняется (раньше затирался).
- **Анимации оживлены** и идут «сверху»: `transform-origin: top center` у
  обёртки, появление — панель падает сверху в позицию с лёгким overshoot
  (`y` −48 → 0, `scale` 0.96 → 1, `ease: 'backOut'`, ~0.42s); закрытие —
  короткий провис вниз и затем панель уходит вверх, уменьшаясь (keyframes
  `y` 0 → 10 → −64, `scale` 1 → 0.99 → 0.94, ~0.24s); затемняющий слой гаснет
  синхронно. `opacity` на панели не анимируется (иначе рвётся
  `backdrop-filter`). При reduced-motion (`useReducedMotionConfig()`) пропы
  `initial`/`animate`/`exit` вообще не передаются — `AnimatePresence`
  монтирует и размонтирует дерево без перехода, включая fade затемняющего
  слоя (его `MotionConfig reducedMotion="user"` сам не глушит — замораживает
  только transform/layout).
- **Пустой футер не рендерится**: если `showCancelButton={false}` и нет ни
  `actions`, ни `leftActions` — блок футера отсутствует целиком (раньше
  оставался пустой отступ). Блок `leftActions` тоже рендерится только при
  наличии содержимого.
- Стили: `offset: 0` (несуществующее свойство) удалён; `backdrop-filter`,
  радиус и внутренний отступ переведены на токены (`--glass-effects`,
  `--modal-border-radius` (24px), `--modal-padding` = `--space-content`);
  типографика заголовка и контента — на `--text-size-*` / `--line-height-*`
  вместо легаси-миксина `paragraph`.
- Сторис переписаны: обзорная статья (анатомия, размеры, закрытие из контента,
  `enabled={false}`) плюс три самостоятельных сценария — публикация статьи
  (асинхронный `actions` + валидация, оставляющая окно открытым), удаление
  воркспейса (подтверждение вводом имени, `disabled` до совпадения),
  ввод PIN (числовой кейпад как единственная задача окна).

Зачем: закрытие модалки вызывало `onClose` дважды и могло дёргать устаревший
колбэк; `role`/`aria-modal` на разных узлах сбивали скринридеры; обращение к
`document` в рендере ломало SSR.
