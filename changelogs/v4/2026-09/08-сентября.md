## Рефакторинг Spoiler

Компонент `Spoiler` приведён к целевому паттерну v4 по заметкам рефакторинга.

Что изменилось:

- **React 19 паттерн**: убран `memo` — обычная функция, `ref` как обычный
  проп прокидывается в корневой `<div>`. Двойной импорт `react` и
  `React.`-нэймспейс убраны, импорт `useBoolean` через алиас `utils`.
- **Заголовок стал нативной `<button>`** вместо `<div tabIndex={0} onClick>`.
  Теперь он фокусируется и переключается с клавиатуры (`Enter` / `Space`) без
  ручных обработчиков, экспонирует `aria-expanded` и `aria-controls` на
  область контента (у неё появился `id` через `useId`). Иконка `+` / `−`
  помечена `aria-hidden` — состояние уже озвучено кнопкой.
- **`title` расширен со `string` до `ReactNode`** — в заголовок можно
  положить строку, лейбл со счётчиком, статус. Появился класс `.Title`
  (`flex: 1`), чтобы такой заголовок раскладывался внутри кнопки. `title`
  добавлен в `Omit` у `SpoilerProps` (перебивает HTML-атрибут `title`).
- **`onToggle`**: тип события уточнён до `MouseEvent<HTMLButtonElement>`.
  Поведение прежнее — вызывается после переключения, `opened` — новое
  состояние.
- **Анимация раскрытия переделана.** Была `height` линейным твином 200 мс —
  дёргалась и выглядела как ~5 fps. Теперь высота идёт near-critically damped
  пружиной (`stiffness 300 / damping 30 / mass 0.8`) на раскрытии и быстрым
  твином 180 мс на закрытии, плюс лёгкий фейд контента. `padding` перенесён с
  анимируемой `.Content` на новый статичный `.ContentInner` — раньше он
  «прыгал» вместе с высотой. Идиома совпадает с `ToastCard` (пружина на вход,
  твин на выход).
- **CSS**: `.Heading` сбрасывает стили кнопки (`appearance`, `border`,
  `background`, `font: inherit`, `width: 100%`, `text-align: left`). Размер
  иконки вынесен в токен `--spoiler-icon-size` (18px) и задаётся на `svg`
  вместо `font-size: inherit`, который на lucide не действовал.
- Сторис переписаны как документация-статья: Overview / Open by default /
  Grouped / Toggle callback / Rich heading and content / Accessibility —
  вместо одного большого демо «App Settings». Unit-тесты переписаны под
  фактическое поведение (свёрнут по умолчанию, раскрытие по клику,
  `aria-expanded`/`aria-controls`, `onToggle`, `ReactNode`-заголовок,
  проброс `ref`); выпилен нерабочий тест на `Configuration` (`Spoiler` его
  не читает, и сам `Configuration` больше не экспортируется) и мёртвый тест
  на атрибут `open` от старой реализации на `<details>`.
- Удалён `REFACTORING.md` — заметки отработаны.

Зачем: закрыть доступность (нефокусируемый `<div>`-заголовок без клавиатуры
и без `aria-expanded`), снять legacy-обвязку (`memo`, `React.`-нэймспейс) и
дать `title` тот же полиморфизм, что у `header` в `Message`.

## Рефакторинг Drawer

Компонент `Drawer` приведён к целевому паттерну v4 — по образцу уже
отрефакторенного `Modal`.

Что изменилось:

- **Доступность.** Панель теперь ловит фокус (`focus-trap-react`) и возвращает
  его на триггер при закрытии; `Escape` закрывает `Drawer`. На теле панели —
  `role="dialog"`, `aria-modal="true"`, `aria-labelledby` (только при наличии
  `title`, через `useId`). Раньше не было ни ловушки фокуса, ни закрытия по
  клавиатуре.
- **SSR / React 19.** Поиск портала вынесен в `getPortalRoot()` с гвардом
  `typeof window`; `ref` прокидывается на корневой элемент оверлея, лишние
  HTML-атрибуты (`restProps`) теперь доходят до него. Клонирование триггера —
  через `DOMUtils.cloneNode` (собственный `onClick` триггера сохраняется).
- **`prefers-reduced-motion`.** При запросе на уменьшение движения slide-in и
  фейд подложки не передаются в `motion` — панель просто монтируется и
  размонтируется (паттерн из `Modal`). Отступ панели от края экрана (8px)
  теперь задаётся в CSS (`.Panel` left/right), а не transform’ом `x` — иначе
  при выключенной анимации панель прилипала к краю. Анимация входа переведена
  со спринга на раздельные кривые: `x` едет по iOS-кривой
  `[0.32, 0.72, 0, 1]` (0.52s), `scale` — easeOutBack `[0.34, 1.56, 0.64, 1]`
  (0.58s) от `0.85` с лёгким перелётом за `1`; `transform-origin` привязан к
  краю экрана, с которого выезжает панель, поэтому масштабирование читается
  как «раскрытие» из края. Выход короче (0.3s, ускоряющаяся кривая) и слегка
  уменьшает панель. На корень `.Drawer` добавлен `overflow: hidden` — пока
  панель на время слайда стоит за краем экрана, она больше не тянет
  горизонтальный скролл страницы.
- **API.** Удалён неиспользуемый проп `showDoneButton`. `content` и `footer`
  теперь принимают render-prop-форму `(ctx: { closeDrawer }) => ReactElement`,
  как `content`/`actions` у `Modal`. `DrawerProps` расширяет
  `HTMLAttributes<HTMLDivElement>`. Поведение `onDone` (возврат `false`
  оставляет панель открытой) без изменений.
- **Кнопки в шапке.** Проп `renderActionButton` (одна кнопка справа) заменён
  на пару `startActions` / `endActions` — каждый принимает один элемент,
  несколько или render-функцию с `closeDrawer`. `endActions` перебивает
  встроенную кнопку Done. Заголовок теперь всегда отцентрован по панели: две
  группы кнопок делят строку поровну (`flex: 1 1 0`), поэтому `title` между
  ними не съезжает независимо от числа кнопок с каждой стороны.
- **CSS.** Разметка выровнена по `Modal`: корневой `.Drawer` (fixed,
  `--level-offcanvas-backdrop`), `.Backdrop`, `.Panel` (`--level-offcanvas`).
  Токены: `--drawer-border-radius` (было `--drawer-rounding`),
  `--drawer-padding: var(--space-content)`, gap через `--gap` / `--l-gap`.
  Исправлена несуществующая переменная `--text-line-height-4` →
  `--line-height-4`. Пустые правила `.Content`/`.DrawerFooter` убраны.
  `.Content` вынесен отрицательными маргинами на края панели, а внутренний
  отступ контента (`--drawer-content-padding`, 12px) задан на обёртке
  `.ScrollInset` *внутри* `Scrollable` — так скролл-вьюпорт обрезает по краю
  панели, а focus-ring и тени у контента до этого края не достают.
- Сторис переписаны по образцу `Modal`: `Overview`-статья (Anatomy /
  Placement / Width / Done button и async `onDone` / Header actions /
  Reduced motion) плюс два самостоятельных сценария в `stories/` —
  `Filter panel` (скролл тела + `footer` с `closeDrawer`) и `Record detail`
  (async `onDone` с валидацией, возврат `false` оставляет панель открытой).
  Старый demo-стори `Deploy Pipeline` удалён — он был на сырых `div` с
  захардкоженными hex-цветами. Добавлены unit-тесты (сохранение `onClick`
  триггера, закрытие по `Escape` и клику по подложке, `onDone` → `false` не
  закрывает, иначе закрывает).
- Удалён `REFACTORING.md` — заметки отработаны.

Зачем: `Drawer` — модальный по поведению оверлей, но не удерживал фокус и не
закрывался с клавиатуры; заодно снята legacy-обвязка и разметка сведена к
общему с `Modal` виду.

## Range: пузырёк со значением рендерится в портал

Пузырёк текущего значения (`showCurrentValue`) у варианта `default` больше не
абсолютно спозиционированный потомок трека, а `@floating-ui/react` +
`FloatingPortal`, привязанный к бегунку (как в `Tooltip`).

Что изменилось:

- Пузырёк выносится в `[data-altrone-root]` и не обрезается `overflow`-предком
  — скроллируемым телом `Drawer`, `Popover`, ячейкой таблицы. Раньше внутри
  скролл-контейнера он срезался по краю.
- Видимость теперь на JS-состоянии (`isActive` / hover / focus-visible),
  потому что портальный элемент вне `.Range` и CSS-селекторы
  `.Range:hover .Value` до него не достают. Появление/исчезновение — через
  `AnimatePresence` (fade 120ms). Публичное поведение `showCurrentValue`
  (`'active'` / `'always'` / `false`) не изменилось.
- Вариант `fill` оставлен как есть — его чип живёт внутри слаба и обрезаться
  не должен.
- CSS: общие визуальные свойства вынесены в `.Value, .ValueFloating`;
  ручное позиционирование (`bottom: calc(100% + 10px)`, `.Vertical .Value`)
  удалено — им занимается floating-ui. Unit-тест на портальность добавлен;
  мёртвый тест на `Configuration` (не экспортируется, `Range` его не читает)
  и тест `renderLabel` на `disabled`-подписи (её больше нет в DOM без
  наведения) переписаны/убраны.

Зачем: значение слайдера пропадало под краем прокрутки в `Drawer` и в любом
другом контексте с обрезкой — портал решает это разом для всех.

## Рефакторинг Scrollable

Компонент приведён к целевому паттерну v4.

Что изменилось:

- **React 19.** Убран `memo` — обычная функция; `ref` — обычный проп. `ref`,
  `className` и `style` теперь все резолвятся на **обёртку** (видимый бокс).
  Раньше `className` уезжал на внутренний элемент OverlayScrollbars, а `ref`
  через `useImperativeHandle` (без deps) отдавал viewport. **Ломающее
  изменение:** для программного скролла viewport теперь достаётся через
  `ref.current?.querySelector('[data-overlayscrollbars-viewport]')`.
- **Новый проп `maxHeight`.** Ограничивает высоту бокса: контент растёт до
  значения, потом скроллится. Без него бокс тянется на всю высоту родителя,
  как и раньше. Заодно чинит существовавший type-error в `AutocompleteInput`
  (`<Scrollable maxHeight="200px">` — проп был в вызове, но не в типах).
- **Мёртвый код убран из типов и не воскрешён:** `direction`, `offset`,
  `maxWidth`, `showShadows`, `onScroll` в публичном API уже отсутствовали —
  подтверждено, что не нужны. `options` OverlayScrollbars мемоизируется по
  `overflowX` / `overflowY`, чтобы без `memo` не переприменяться каждый рендер.
- **CSS.** Классы переименованы (`.Scrollable` — обёртка, `.Os` — хост
  OverlayScrollbars), лишний инлайновый `height: 100%` убран (дублировал
  класс). Импорт своей темы через относительный путь.
- Сторис переписаны как документация-статья (Filling a sized parent /
  maxHeight / Per-axis overflow / Inside a flex column). Unit-тесты: проверка,
  что `ref`/`className`/`style` идут на обёртку, и что `maxHeight` снимает
  `height: 100%`; выпилен нерабочий тест на `Configuration` (`Scrollable` его
  не читает, и сам `Configuration` не экспортируется).
- Удалён `REFACTORING.md` — заметки отработаны.

Зачем: половина публичного API была фиктивной, `className` и `ref` указывали
на разные узлы, а частая реальная потребность (ограничить высоту скролл-бокса)
не поддерживалась — при этом вызов с `maxHeight` уже был в коде и падал
типами.

## Рефакторинг Form

Компонент приведён к целевому паттерну v4.

Что изменилось:

- **React 19.** Убран `memo` с `Form` и `Field` — обычные функции. `memo`
  на `Form` заодно **стирал generic-параметр** `<FormState>` (возвращался
  `MemoExoticComponent`), теперь `<Form<MyState>>` снова работает.
- **Нативный `action`.** `handleSubmit` вызывает `preventDefault()` только
  если у формы нет пропа `action` — так `<Form action={serverAction}>`
  (Server Action) не блокируется. `onSubmit` вызывается как и раньше.
- **Тип `errorMessages`** переписан на
  `Partial<Record<keyof FormState | (string & {}), string | null | undefined>>`
  — ключи `FormState` автокомплитятся, любая другая строка тоже принимается,
  и `{}` теперь валиден (старый `Record<keyof FormState | string, …>` требовал
  все ключи).
- **CSS.** Обёртка полей вынесена из инлайнового `<Flex gap="l">` в класс
  `.FieldStack` c токеном `--form-field-gap` (то же значение `--l-gap`, 0
  визуального диффа). В `Field` отступ иконки-подсказки: `--s-gap` →
  `--space-inline` (семантика, значение то же).
- **`Field`**: убран бессмысленный `styles = { ...style }`, поиск ошибки по
  `name` защищён (`name ? … : undefined` вместо `String(name)` →
  `"undefined"`).
- Unit-тесты: тест на иконку-подсказку переписан с несуществующего
  `getByText('help_outline')` (старый Material-icon) на поиск кнопки по
  `aria-label`; добавлен тест на `preventDefault` (гасится без `action`,
  не гасится с `action`); выпилен нерабочий тест на `Configuration`
  (`Form` его не читает, и `Configuration` не экспортируется).
- Удалён `REFACTORING.md` — заметки отработаны.

Зачем: `memo` ломал типовой generic и лишний ре-рендер, `preventDefault`
без условия закрывал дорогу Server Actions, а тип `errorMessages` был
дефектным (требовал все строковые ключи).

## Switcher: непрозрачный фон трека

Фон трека `Switcher` переведён с alpha-токенов на сплошные: `--interactive-a1`

## Рефакторинг Splitter

Компонент приведён к целевому паттерну v4. Логика drag/collapse не менялась.

Что изменилось:

- **React 19.** Убран `memo` с `Splitter` и `SplitterDivider` — обычные
  функции. На `Divider` `memo` всё равно был бесполезен: пропы
  `onCollapseLeft/Right` — инлайновые стрелки, пересоздавались каждый рендер.
  `React.`-нэймспейс заменён именованными импортами (`Children`, `Fragment`,
  типы событий).
- **Локализация.** Кнопки сворачивания на разделителе больше не
  захардкожены (`'Collapse panel'` / `'Expand panel'`), `aria-label` панелей
  тоже — всё через `useLocalization()`. Добавлена секция `splitter`
  (`collapsePanel` / `expandPanel` / `panel`) во все 5 словарей и в
  `Localization`.
- **API.** Удалён проп `size` у `Splitter.Panel` — он был синонимом
  `defaultSize` с вводящим в заблуждение именем (namespace `size` в проекте
  означает `mini/s/m/l/xl`). Используйте `defaultSize`.
- **Новый проп `collapsedControlsVisibility`** (`'always'` | `'hover'` |
  `'never'`, дефолт `'always'`) — как показывать кнопку раскрытия у свёрнутой
  панели: закреплённой, только по ховеру разделителя, или не рендерить вовсе
  (тогда раскрытие — через `controlRef`). Экспортирован тип
  `SplitterCollapsedControlsVisibility`. Заодно ховер-раскрытие кнопок теперь
  работает и на «отключённом» разделителе (он отключается для драга, пока
  сосед свёрнут), иначе в режиме `'hover'` кнопку было не достать.
- **Починены кнопки сворачивания.** Раньше `.CollapseBtn` был
  `pointer-events: none`, пока разделитель не в `:hover`, а сама зона ховера —
  тонкая 10px-полоса. Кнопки шире полосы, поэтому клик по ним часто попадал в
  разделитель и начинал ресайз вместо сворачивания. Теперь кнопки всегда
  hit-testable (видимость по-прежнему по ховеру/фокусу), а `handlePointerDown`
  в `useSplitterDrag` игнорирует нажатие, если оно пришло с `<button>`.
- **CSS.** Все `::before`-правила у разделителя удалены — они были мёртвыми
  (ни у одного не было `content`, псевдоэлемент не рендерился). Фокус/актив
  разделителя и так показываются через цвет ручки. Захардкоженные длительности
  анимаций (`0.2s ease`, `0.15s`) → токены `--motion-duration-{base,fast}` /
  `--motion-easing-standard` (теперь уважают `prefers-reduced-motion`).
  `border-radius: 9999px` → `--radius-pill`. Мёртвые токены
  `--splitter-line-size` / `--splitter-collapse-btn-{size,icon}` удалены.
  `overflow: hidden` у свёрнутой панели вынесен из инлайн-стиля в класс
  `.PanelCollapsed`.
- Тулбар в сторис `External control` переписан с сырых `<button>` на `Button`.
  Добавлен `vitest/splitter.test.tsx` (число панелей/разделителей, `defaultSize`
  → flex, imperative `toggle` + `onCollapse`, клик по кнопке сворачивания,
  локализованный лейбл и `showControls={false}`).

Зачем: снять legacy-обвязку (`memo`, `React.`-нэймспейс), убрать
захардкоженные строки и мёртвый CSS, и выкинуть дублирующий проп `size`.

## Toolbar стал универсальным (variant / size)

`Toolbar` перестал быть только плавающей стеклянной панелью поверх канваса —
теперь одним компонентом собираются шапка приложения, шапка фрейма/панели и
оверлей над контентом.

Что изменилось:

- **Новый проп `variant`** (`'plain'` | `'floating'` | `'glass'`, дефолт
  `'glass'`) — задаёт количество «хрома» от минимума к максимуму:
  - `plain` — нет фона тулбара, у `Toolbar.Group` нет материала: плоские
    text-кнопки. Для панели на поверхности, которая уже рисует свой фон
    (например, `Screen.Header`).
  - `floating` — фона тулбара нет, но каждая `Toolbar.Group` — приподнятая
    стеклянная пилюля; полоса приклеена к краю `placement` ближайшего
    позиционированного предка и прозрачна для кликов между пилюлями.
  - `glass` — акцентно-тонированная (`--color-header-backdrop`) размытая
    заливка тулбара с хайрлайном по кромке, обращённой к контенту, плюс те
    же стеклянные пилюли; drop-shadow добавляется только под `sticky`
    (эффект «уплотнения» при скролле). Самодостаточная шапка.
- **Визуальный язык — Apple liquid glass.** Пилюля `Toolbar.Group`
  (`--radius-pill`-капсула): полупрозрачная заливка `--glass-background-color`,
  сильное `backdrop-filter` размытие `--glass-effects`, specular-блик по
  верхней кромке (`inset 0 1px 0`), тонкий rim по контуру, мягкая тень.
  Component-scoped токены `--toolbar-pill-{fill,blur}` /
  `--toolbar-glass-{fill,blur,rim,highlight}` на `.Toolbar`; `highlight`
  приглушается в тёмной теме.
- **Новый проп `size`** (`mini/s/m/l/xl`, дефолт `m`) — задаёт высоту и
  внутренние отступы тулбара, масштабирует `Toolbar.Title`
  (`--toolbar-title-size`/`-line-height`, `--text-size-3…7`) и каскадом
  становится дефолтным `size` для каждого вложенного `Toolbar.Action`
  (переопределяется на самом действии).
- **`fixed` → `sticky`.** `fixed` (накладывал `position: absolute`)
  помечен deprecated и продолжает работать как `sticky` (`position:
  sticky` к краю `placement`) до v4; выводит `deprecatedMessage`.
- **Раскладка секций переехала с `position: absolute` на CSS-грид.**
  `Toolbar.Leading` / `Center` / `Trailing` раскладываются треком
  `1fr auto 1fr` — центр оптически по центру независимо от ширины боковых
  секций, без перекрытий. Для вертикального `placement` — то же гридом по
  строкам. Секции помечены `data-toolbar-region`, чтобы `:has()` работал
  через границу CSS-модуля.
- **Новый `Toolbar.Separator`** — `variant="space"` (дефолт, гибкий
  `flex: 1`, отжимает следующий блок к краю) или `variant="line"`
  (хайрлайн-разделитель между группами, `role="separator"`).
- **Новый `Toolbar.Logo`** — слот под лого продукта (`<svg>`/`<img>` в
  children), сжимается в квадрат `--toolbar-logo-size` (24…40px по тиру
  `size`). Навигацию домой вешает потребитель (`<a>` / `onClick`).
- **`Toolbar.Group`**: вид пилюли наследуется от `variant` тулбара
  (пилюля в `floating`/`glass`, просто ряд в `plain`), но проп `variant`
  на группе переопределяет это точечно — пилюля-группа внутри
  `plain`-тулбара или плоский кластер внутри `glass`. Совсем без
  контейнера — действия кладут в тулбар/секцию напрямую. Классы
  выравнивания переименованы `Center/End/Between` →
  `AlignCenter/AlignEnd/AlignBetween` — раньше `align="center"`
  конфликтовал в CSS-модуле с классом секции `Center`.
- **`Toolbar.Title`**: `text-shadow` (для читаемости поверх произвольного
  контента) остался только под `floating`. Размер шрифта следует за `size`
  тулбара. `clickable` (заголовок — триггер поповера/меню, оборачивается в
  `Dropdown`) добавляет шеврон, `cursor: pointer` и `user-select: none`;
  статический заголовок — просто текст. Шеврон теперь bare `aria-hidden`
  иконка (`width: 1em`, тянется за размером заголовка) вместо фантомной
  `<Button aria-label="Open">` — ушла захардкоженная строка и лишний
  элемент из a11y-дерева.
- **Контекст.** `ToolbarPlacementContext` заменён на `ToolbarContext`
  (`placement` / `orientation` / `variant` / `size`) — внутренний, из
  публичного API не экспортировался.
- **CSS почищен**: мёртвый класс `.Fixed` (`position: absolute` при
  семантике «fixed»), неиспользуемые `--toolbarAction*`-переменные,
  захардкоженные px заменены токенами (`--space-inline`, gap-scale).
- Сторис переписаны как документация-статья: Overview / Variants (три
  варианта бок о бок над цветным контентом) / Application header / Frame ·
  panel toolbar / Component doc header (`Toolbar.Logo`) / Sizes / Title —
  static vs. menu / Vertical rail / Header action presets / Floating
  overlay (design canvas). Unit-тесты: каскад
  `size` на `Toolbar.Action`, deprecation `fixed`, структурный контракт
  `floating` (внутренний click-through слой), пилюля группы во всех
  вариантах кроме `plain`, шеврон у `Toolbar.Title` только при `clickable`,
  `Toolbar.Logo` рендерит children и пробрасывает `ref`; выпилен нерабочий
  тест на `Configuration` (`Toolbar` его не читает, и сам
  `Configuration` больше не экспортируется).
- Удалён `REFACTORING.md` — заметки отработаны.

Зачем: компонент назывался «панель инструментов», но по вёрстке был жёстко
заточен под один сценарий (плавающий оверлей) — стеклянные пилюли,
перекрывающиеся абсолютные секции, фикс. высота 56px. Для шапки приложения
или фрейма это неудобно; `variant` + `size` + потоковая раскладка секций
делают все три сценария одинаково короткими в вёрстке.

## Рефакторинг NavigationList

Компонент `NavigationList` и его подкомпоненты приведены в порядок по заметкам
рефакторинга.

Что изменилось:

- **`NavigationList.Link` теперь рендерит нативный `<a>`** вместо `<div onClick>`.
  Появилась настоящая доступность: с `href` — обычная ссылка; без `href` (режим
  «кнопки») элемент фокусируется и активируется с клавиатуры (`Enter` / `Space`).
  Выбранный пункт (`selected`) проставляет `aria-current="page"`.
- **Проп `disabled` наконец работает.** Раньше был объявлен в типах и в сторис,
  но игнорировался. Теперь у выключенного пункта снимается `href`, ставится
  `tabindex="-1"` и `aria-disabled`, клики глушатся; в стилях — `.Disabled`
  через `--disabled-text-color` (без opacity).
- **`NavigationListLinkProps`** переведён с `HTMLAttributes<HTMLDivElement>` на
  `AnchorHTMLAttributes<HTMLAnchorElement>` — `href`, `target`, `rel` и т.п.
  теперь валидны; `ref` — на `HTMLAnchorElement`. Внутренние пропы
  (`selected` / `disabled` / `icon` / `label` / `badge`) больше не утекают в DOM.
- **`NavigationList.Group`** экспонирует `role="group"` + `aria-label={title}`.
  Шапка группы (`.Header`) больше не рендерится, если нет ни `title`, ни
  `GroupAction` — раньше выводился пустой `<div>` с отступом.
- **Удалён мёртвый код**: неиспользуемые `groupAction.module.scss` и
  `linkAction.module.scss` (обе кнопки рендерят `Button`); в `link.module.scss` —
  псевдоэлемент `&:before` (ссылался на несуществующую переменную) и класс
  `.NestedList`. Убраны пустые операции (`{...style}`, `clsx(className)`,
  `titleCls`) в `NavigationList`, `Group`, `GroupAction`, `LinkAction`.
- **Выделение пункта теперь анимируется.** Заливка выбранного пункта вынесена
  с `.Link` на отдельный слой `.SelectedBackdrop` (`motion.div` с общим
  `layoutId` на уровень вложенности) — при смене выбора она плавно
  переезжает между пунктами (спринг без перелёта). Цвет текста
  переходит по `transition`. Весь список обёрнут в `LayoutGroup`.
- **Подложка при наведении переделана на один общий элемент.** Раньше это был
  `motion.div` в каждом пункте, который монтировался/размонтировался на каждом
  движении курсора — отсюда мерцание и вылет «из угла». Теперь `NavigationList`
  рендерит одну `.HoverBackdrop`: слушает `mouseover`, через
  `closest('[data-nav-link]')` находит пункт под курсором, замеряет его
  прямоугольник и двигает подложку туда пружиной. Появляется она fade-ом
  на месте (позиция уже в `initial`), а не выезжает. Прячется (opacity → 0,
  0.18s, без ремоунта) когда курсор не над пунктом — над выбранным/выключенным,
  в отступах между группами, в шапке/подвале, за пределами списка. Между
  обычными пунктами — плавный переезд без мерцания. Клик по наведённому пункту
  гасит подложку через `NavigationListHideHoverContext` (события мыши при этом
  не летят).
- **Бейджи переведены на `Box`-пилюлю** (`shape="pill"` / `material="translucent"`
  / `tone="neutral"`) с той же размерной настройкой, что у бейджей в `Button` —
  вместо самодельного `.Badge` на базе библиотечного `Badge`. Токены
  `--navigation-list-badge-*` подогнаны под `--button-badge-*`.
- **Текст рендерится через `Text`**: подпись пункта (`Link`) и заголовок группы
  (`Group`) — `Text` с `truncate` вместо голых `div`. Значение бейджа —
  `Text` для строк/чисел.
- **Шапка и подвал получили фон.** `Header` / `Footer` — `position: sticky`, но
  без фона текст наезжал на прокручиваемые пункты. Добавлен сплошной
  `background` (`--navigation-list-chrome-background-color` → `--background-1`) и
  разделительная линия (`--navigation-list-chrome-border-color`). Обе полосы
  выходят за паддинг контейнера отрицательными маргинами
  (`--navigation-list-padding`) — занимают всю ширину. В состоянии покоя их
  внешние углы повторяют скругление контейнера (`--navigation-list-rounding`);
  когда полоса закреплена (стик), скругление убирается. «Закреплённость»
  определяет хук `useStuck` (`IntersectionObserver` по элементу со смещением
  `-1px` за край, `root` — ближайший скролл-контейнер), выставляя `data-stuck`.
- **Отступы.** `gap` в ряду пункта (`.Label`) — 4px; у иконки дополнительный
  `margin-right: 4px`, чтобы отступ иконка→подпись остался 8px. По вертикали
  пункты меню в группе идут вплотную (без `gap`); заголовок группы отбит от
  списка `margin-bottom: 4px`.
- **`LinkAction`** переведён с `variant="text"` на дефолтный вариант `Button`
  (материал `plate`) — экшены в пунктах меню стали заметными кнопками.
- **CSS-переменные**: добавлено определение
  `--navigation-list-secondary-link-border-color` (было использование без
  объявления).
- Юнит-тесты переписаны (старые падали на удалённом `Icon` и вырезанной
  интеграции с `useConfiguration`): `<nav>` + className/style, `<a>` +
  `aria-current`, `disabled` (нет клика, вне таб-порядка), активация с
  клавиатуры, `LinkAction` не триггерит родителя, раскрытие вложенных ссылок.
- Сторис переписаны как документация-статья: раздел Overview с прозой (анатомия,
  группы, вложенные ссылки, row/group actions, бейджи, disabled, `asChild` для
  роутерных ссылок) плюс три «боевых» сценария — Project Management, Code
  Repository, E-commerce Admin.
- Удалён `REFACTORING.md` — заметки отработаны.

Зачем: `NavigationList` — основная навигация приложения, а его пункты не были
ни ссылками, ни кнопками с точки зрения доступности; `disabled` не действовал.
Заодно вычищен код, накопившийся от предыдущих незавершённых заходов.

## Рефакторинг BottomNavigation

Компонент `BottomNavigation` и его `Item` приведены в порядок по заметкам
рефакторинга.

Что изменилось:

- **Компактнее и по сетке.** Иконка 28→24px, паддинг пункта 8→6/10px,
  `min-width` 80→64px, скругление панели 40→22px, пункта 32→18px
  (концентрично: 22 − 4px паддинга). Мёртвые/несуществующие CSS-переменные
  (`--bottom-navigation-item-backdrop-color-selected`,
  `--bottom-navigation-badge-background`, …) убраны; размеры вынесены в токены
  (`--bottom-navigation-item-icon-size`, `-rounding`, `-min-width`,
  `-padding`).
- **Бейджи — как у кнопки с одной иконкой.** Вместо библиотечного `Badge` с
  самодельным `.Badge` теперь `Box` (`shape="pill"` / `material="plate"` /
  `tone="neutral"`) в правом верхнем углу со смещением `translate(35%, -35%)` —
  та же идиома, что у corner-бейджа `Button`. Токены `--bottom-navigation-badge-*`
  подогнаны под `--button-badge-*` (20px, шрифт 10px).
- **`asChild` вместо `renderFunc`.** Добавлен проп `asChild` (Slot-паттерн: стили,
  `ref` и обработчики переносятся на дочерний элемент роутера, иконка/подпись/
  бейдж/подложка остаются от `Item`). `renderFunc` сохранён рабочим, но помечен
  `@deprecated`. Выбранный пункт проставляет `aria-current="page"`.
- **React 19 / чистка.** `Item` больше не строится через `renderFunc`-индирекцию
  с дефолтным `bottomNavigationItemComponent`; рендер `<a>` инлайновый. Импорт
  `framer-motion` → `motion/react`. Текст подписи — через `Text` (`truncate`),
  значение бейджа — `Text` для строк/чисел. Русский эмодзи-комментарий заменён
  на английский. Убраны пустые операции (`{...style}`), `gap` между пунктами.
- **Подложка выбора переехала на один общий элемент.** Раньше это был
  `motion.div` с общим `layoutId` в каждом выбранном пункте — из-за
  cross-component `layoutId` первый переход после монтирования происходил
  скачком (анимировались только последующие). Теперь `BottomNavigation`
  рендерит одну подложку и двигает её пружиной на выбранный пункт: пункт
  сообщает свой элемент через контекст (`useEffect` на `selected`), контейнер
  замеряет его прямоугольник (плюс `ResizeObserver` на перекладку). Скейл-пульс
  `[1, 0.85, 1]` на каждом переезде сохранён (на отдельном вложенном
  `motion.div`), кроме первичной установки. Первый клик теперь анимируется.
- Юнит-тесты переписаны (старые падали на удалённом `Icon` и вырезанной
  интеграции с `useConfiguration`): контейнер + className/style, `<a>` +
  `aria-current`, бейдж, `onClick`, `asChild` (контент внутри кастомного
  элемента), `renderFunc` всё ещё подменяет элемент.
- Сторис переписаны как документация-статья: Overview с прозой (анатомия,
  бейджи, floating vs flush, роутер) плюс три сценария в телефонной рамке —
  Music app, Mobile banking, Social feed — и отдельная Floating-история.
- Синхронизированы `mcp/docs/BottomNavigation.md` и
  `docs/content/ru/bottomNavigation.md` (бейдж, размеры, `asChild`,
  `aria-current`). Удалён `REFACTORING.md` — заметки отработаны.

Зачем: панель была крупнее сетки размеров и с собственной вёрсткой бейджа;
`renderFunc`-индирекция и импорт `framer-motion` расходились с остальной
библиотекой.

## Рефакторинг SideNavigation

Компонент `SideNavigation` (on-page оглавление со scroll-spy) приведён в порядок
по заметкам рефакторинга. Публичный API почти не изменился.

Что изменилось:

- **Удалён мёртвый код.** `SideNavigation.context.ts` (`SideNavigationContext` /
  `useCurrentSideNavigation`) и тип `SideNavigationContextType` — ни на что не
  ссылались (состояние приходит из `ScrollSpy`/`useScrollSpy`), удалены.
- **`Item` пробрасывает `ref`** на корневой `<li>` (`SideNavigationItemProps`
  теперь несёт `ref?: Ref<HTMLLIElement>`). `className`/`style` тоже уходят на
  `<li>` (раньше `style` утекал на вложенный `<a>` через `restProps`, а
  `className` был на `<li>` — рассинхрон). База типа — `AnchorHTMLAttributes`
  (были только `HTMLAttributes`), так что `target`/`rel`/`download` теперь
  валидны и доходят до `<a>`.
- **Доступность.** У `<nav>` появился `aria-labelledby` на заголовок (заголовок
  рендерится через `Text` с `id` от `useId`). `aria-current="page"` на активном
  пункте — уже было.
- **Типографика по токенам.** В `item.module.scss` захардкоженные
  `font-weight: 500` / `line-height: 20px` у `.Label` → `var(--text-weight-medium)`
  / `var(--line-height-4)`, у `.Selected .Label` `600` → `var(--text-weight-bold)`.
  Из `transition` убран неанимируемый `font-weight`. Заголовок в
  `SideNavigation.tsx` — `Text` (`size={4}` / `weight="medium"` / `block`)
  вместо голого `<div>`; дублирующие декларации из `.Title` в SCSS убраны.
- **Чистка `SideNavigation.tsx`:** убраны пустые операции (`titleCls =
  clsx(s.Title)`, `styles = {...style}`).
- Добавлены юнит-тесты (не было ни одного): `<nav>` + `aria-labelledby` +
  проброс `ref`/className/style, `Item` = `<li>` с вложенным `<a href>` и
  пробросом `ref`, вложенные пункты внутри дочернего списка.
- Сторис переписаны как документация-статья: Overview с прозой (что это, отличие
  от `NavigationList`, анатомия, вложенность) + `Documentation page` (живой
  scroll-spy на секциях из массива, компактнее прежней 250-строчной простыни) +
  `Without title`.
- Обновлён `mcp/docs/SideNavigation.md` (`ref` у `Item`, `aria-labelledby`).
  Удалён `REFACTORING.md`.

Зачем: снять мёртвый контекст-слой, закрыть проброс `ref` (требование проекта)
и захардкоженную типографику, дать `<nav>` доступное имя.

## Рефакторинг Tabs

Компонент `Tabs` дочищен по заметкам рефакторинга (React 19 / `motion/react` /
уникальный `layoutId` уже были сделаны раньше).

Что изменилось:

- **`Tabs.Item` по умолчанию — `<button type="button">`, а не `<a>` без `href`.**
  Все реальные использования (`ColorPicker`, сторис) — это переключатели
  вида (`onClick` + `selected`), а `<a>` без `href` не фокусируется и не
  активируется с клавиатуры. `<a href>` рендерится только когда передан `href`.
- **Клавиатура по WAI-ARIA tabs.** У `Tabs` появился `onKeyDown`:
  `←`/`→`/`↑`/`↓` и `Home`/`End` перемещают фокус между вкладками (пропуская
  `disabled`), `Enter`/`Space` активируют нативно. Таб-стопом является выбранная
  вкладка (`tabindex={0}`, у остальных `-1`). `ref` компонента теперь
  композится с внутренним `rootRef`.
- **Проп `disabled`** у `Tabs.Item` — вкладка не фокусируется, не кликается,
  пропускается стрелками; в стилях `.Disabled` через `--disabled-text-color`.

- **`Text` для подписи** вместо `<div className={s.Label}>`. У icon-only вкладки
  (`showLabel={false}`) `label` уходит в `aria-label`.
- **CSS**: `.Item` получил ресеты для `<button>` (`border: none`,

  фона на `:focus-visible`). Убрана пустая операция `styles = {...style}` в

- `renderFunc` помечен `@deprecated` (в пользу `asChild`), но работает.
- Юнит-тесты переписаны (старый тест на `Configuration` был вырожденным —

- Сторис: добавлен раздел `Overview` с прозой (анатомия, `button` vs `href`,

- Обновлён `mcp/docs/Tabs.md` (элемент по умолчанию, клавиатура, `disabled`,

## Рефакторинг Breadcrumbs

Компонент `Breadcrumbs` дочищен по заметкам рефакторинга.

Что изменилось:

- **Разделитель без хрупкой инъекции `isLast`.** Раньше `Breadcrumbs`
  прогонял `Children.toArray` + `cloneElement`, подставляя каждому потомку
  внутренний проп `isLast` — это ломалось на обёрнутых элементах (последняя
  крошка внутри `Dropdown` не получала бы `isLast`). Теперь `Item` всегда
  рендерит разделитель (`aria-hidden`), а прячется он на `.ListItem:last-child`
  через CSS — корректно независимо от обёрток. Проп `isLast` и вся логика
  `Children`/`cloneElement` в `Breadcrumbs.tsx` удалены.
- **`asChild` больше не теряет пропы.** В ветке `asChild` на `Slot` уходил
  только `className`; `onClick`, `data-*`, `aria-*` и прочий `restProps`
  игнорировались. Теперь общий объект пропов (`className` + `aria-current` +
  `restProps`) идёт и в `Slot`, и в дефолтный `<div>`.
- **`current` проставляет `aria-current="page"`** на элементе крошки
  автоматически (раньше — только визуальный стиль, `aria-current` был на
  совести потребителя).
- **Локализованный `aria-label` у `<nav>`.** Добавлен ключ `breadcrumbs.label`
  во все пять словарей (`en`/`ru`/`fr`/`ge`/`sp`) — landmark-навигация теперь
  различима среди других `<nav>` на странице.
- **`Text` для подписи** вместо `<div className={s.Label}>` (с `truncate`);
  `.Item .Label { color: inherit }`, чтобы подпись следовала за цветом крошки
  (hover / current-акцент).
- **Типы.** `BreadcrumbsItemProps` — убран `isLast`, база `HTMLAttributes<HTMLElement>`
  (было `HTMLDivElement`, хотя корень — `<li>`, а элемент при `asChild` —
  произвольный), `ref` — `Ref<HTMLElement>`.
- **CSS.** Пустое правило `.Breadcrumbs {}` → `display: flex; min-width: 0`;
  `.List` получил `flex-wrap: wrap` (длинный путь переносится, а не
  переполняет). `--breadcrumbs-text-size` → `var(--text-size-4)` вместо
  захардкоженных `14px`. Убрана пустая операция `styles = {...style}` в
  `Breadcrumbs.tsx`; `Item` стал `memo`.
- Юнит-тесты переписаны (старый тест на `Configuration` был вырожденным):
  `<nav>` с доступным именем + `<ol>` + проброс `ref`/className/style, `<li>` +
  `aria-current` на current, `asChild` (контент внутри `<a>` + проброс
  `onClick`), ошибка при невалидном `children`.
- Сторис переписаны как документация-статья: `Overview` с прозой (plain vs
  links, `current`, свёрнутый путь через `Dropdown`) + сценарий `File browser`.
- Синхронизированы `mcp/docs/Breadcrumbs.md` и `docs/content/ru/breadcrumbs.md`
  (`aria-current` автоматом, разделитель через CSS, `aria-label`, `ref`).
  Удалён `REFACTORING.md`.

Зачем: инъекция `isLast` через `cloneElement` — хрупкий приём, ломавшийся на
обёртках; `asChild` молча терял обработчики; `current` не был доступен
скринридеру.

## Рефакторинг Pagination

Компонент `Pagination` дочищен (крупный переписанный слой — controlled-модель,
`onChange` с событием, `buildPageItems`, локализация, проброс `ref` — уже был
сделан раньше).

Что изменилось:

- **Семантика `<nav>` вместо `role="navigation"` на `div`.** Рендер через
  `<Flex tagName="nav">` — нативный landmark с локализованным `aria-label`
  (`pagination.navigation`).
- **Текущая страница остаётся фокусируемой.** Раньше кнопка текущей страницы
  была `disabled` — недоступна с клавиатуры, скринридер не мог до неё
  дотабиться и услышать `aria-current="page"`. Теперь только `selected` +
  `aria-current`, `onClick` работает (повторный выбор той же страницы —
  безвредный no-op для потребителя).
- **Dev-предупреждение при выходе `currentPage` за пределы `1..totalPages`.**
  Компонент по-прежнему ничего не сбрасывает (controlled), но подсказывает в
  консоли (`import.meta.env.DEV`), что зажимать значение должен потребитель.
- **CSS**: `width: fit-content` перенесён с инлайнового `style` в
  `.Pagination`. Убрана пустая операция `styles = { ...style }`.
- **Типы**: `PaginationProps` — база `HTMLAttributes<HTMLElement>` (было
  `HTMLDivElement`, хотя рендерится `<nav>`), с `Omit<..., 'onChange'>` чтобы
  собственный `onChange(page, event)` не конфликтовал с `FormEventHandler`;
  `ref` — `Ref<HTMLElement>`.
- Юнит-тесты переписаны полностью (старые были на удалённом API `setPage` /
  тексте «2 of 8» и вырожденном `Configuration`): `<nav>` + доступное имя +
  проброс `ref`/className/style, `aria-current` на текущей, disabled
  prev/first на первой и next/last на последней странице, `onChange(page,
  event)`, эллипсис и первая/последняя страницы при широком диапазоне,
  `siblings`, `showEdgeButtons={false}`.
- Сторис переписаны как документация-статья: `Overview` с прозой (controlled-
  модель, окно номеров + `siblings` + эллипсис, доступность) плюс набор
  вариаций и отдельная `Interactive`-история с `args`.
- Обновлён `mcp/docs/Pagination.md` (`<nav>` + `aria-label`, `onChange` с
  событием, `showEdgeButtons` default `true`, `ref` тип, поведение при
  `totalPages = 1` — рендерится, не прячется). Удалён `REFACTORING.md`.

Зачем: `role="navigation"` на `div` вместо `<nav>`; недоступная (disabled)
кнопка текущей страницы; молчаливое поведение при невалидном `currentPage`.

## Редизайн и рефакторинг Empty

`Empty` из «иконка + одна строка» переработан в полноценный empty-state-блок по
образцу подобных компонентов в других дизайн-системах (Chakra `EmptyState`,
shadcn `Empty`, Ant `Empty`).

Что изменилось:

- **Новая структура и вид.** Иконка теперь сидит в мягком круглом media-чипе
  (`--interactive-1`), под ней — короткий заголовок (`title`), опциональная
  приглушённая строка описания (`description`) с ограничением ширины и
  `text-wrap: pretty`, и опциональный ряд кнопок (`actions`). Всё по центру.
- **Новые пропы**: `title`, `description`, `actions`, `size` (полная шкала
  `mini`/`s`/`m`/`l`/`xl`, дефолт `'m'` — масштабирует чип, типографику и
  паддинги). `EmptyProps` расширяет
  `Omit<HTMLAttributes<HTMLDivElement>, 'title'>` (свой `title: ReactNode`
  перебивает HTML-атрибут).
- **Обратная совместимость.** `children` работает как алиас `description`; при
  отсутствии явного `title` одиночная строка (`children`/`description`)
  становится заголовком — `<Empty>No projects yet</Empty>` рендерится как одна
  строка, как раньше. Без пропов — дефолтный заголовок из `empty.noData`.
- **Удалён проп `transparent`** — он был полностью мёртвым (селектор
  `.Transparent .Empty` никогда не совпадал, а фона/бордера у `.Empty` не было).
  Консьюмер `AutocompleteInput` (`<Empty transparent />`) переведён на
  `<Empty size="s" />`; в `DataTable` панель фильтров — тоже `size="s"`.
- Текст рендерится через `Text` (`title` — `weight="medium"`, `description` —
  `color="muted"`), размеры привязаны к `size`. Иконка в чипе масштабируется
  через `font-size` + `svg { width/height: 1em }`.
- Юнит-тесты переписаны (старые падали на удалённом `Icon` и вырезанном
  `Configuration`): `role="status"` + дефолтный заголовок, промоушен одиночной
  строки в заголовок, `title` + `description`, кастомная иконка и `actions`,
  размерный модификатор, проброс `ref`/className/style.
- Сторис переписаны как документация-статья: `Overview` (анатомия, размеры,
  «одна строка») плюс сценарии — No search results, Inbox zero, First run (с
  кнопками), Failed to load.
- Обновлены `mcp/docs/Empty.md` (новый API) и `docs/content/ru/screen.md`
  (`<Empty label=…>` → `<Empty>…</Empty>` — пропа `label` никогда не было).
  Удалён `REFACTORING.md`.

Зачем: прежний `Empty` умел только иконку и одну строку — не хватало
заголовка/описания/действий, которые есть у empty-state в любой зрелой
дизайн-системе.
