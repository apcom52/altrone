# История релизов Altrone UI: 1.0 — 4.0 (бета)

Сводный ретроспективный чейнджлог по всем продовым релизам от 1.0 до 3.5, а также по грядущей версии 4.0 (пока в бете), сгруппированный по компонентам. Собран из GitHub Releases (https://github.com/apcom52/altrone-ui/releases) для последующего использования при формировании истории версий каждого компонента в документации.

Это **не** обычный ежедневный changelog-файл по правилу `changelog.md` — отдельный сводный документ по историческим релизам, предшествующим и включающим текущую `v4`-разработку.

**Учтённые релизы:** 1.0 (1.0.0–1.0.6), 1.1 (1.1.0–1.1.3), 1.2 (1.2.0–1.2.5), 1.3 (1.3.0–1.3.7), 2.0 (2.0.0–2.0.5), 2.1 (2.1.0–2.1.3), 2.2 (2.2.0–2.2.1), 3.0 (3.0.0–3.0.4), 3.1 (3.1.0–3.1.3), 3.2 (3.2.1–3.2.3), 3.3 (3.3.0), 3.4 (3.4.0), 3.5 (3.5.0), 4.0 (бета, 27 сентября 2026; финальный стабильный релиз на момент составления документа ещё не вышел).

**Переименования компонентов, о которых нужно знать при чтении:** в релизе 3.0 библиотека была переписана с нуля, и часть компонентов сменила название вместе с переработкой API. В этом документе история приводится под текущим именем компонента, а старое указано в скобках при первом упоминании: `FloatingBox` → `Popover`, `ContextMenu` → `Dropdown`, `CheckboxList` → `CollapsedList`, `TabList` → `Tabs`, `Switcher` → `Switch`, `Toast`/`sendNotification` → `Notifications`, `Range` (появился в 3.5) → `Slider`. Для `Chips` → `Tags` и `RadioList` → `Radio` прямого подтверждения переименования в релиз-нотах нет, но по смыслу компонентов это наиболее вероятная линия преемственности — учитывайте это при построении версионной истории. При переходе на архитектуру 4.0 произошла ещё одна волна переименований: `AltroneApplication` → `Application`, `Empty` → `Result` (с расширением до полноценного фидбек-компонента), `Switcher` → `Switch` (окончательно), `Range` → `Slider` (окончательно), `Textarea` → `TextArea`. Компоненты `Screen`, `Image`, `Drawer`, `Splitter`, `Dialogs` (императивный `showAlert`/`showConfirm`/`showPrompt`), `Result`, `Label` и `Skeleton` в релизах 1.0–3.5 не упоминаются вовсе — все они впервые появились в 4.0.

Каждый раздел компонента, помимо краткого прозаического описания, содержит блок **«История по версиям»** — детальный список изменений по каждому релизу, где что-то менялось (в порядке от новой версии к старой). В отличие от прозы, сюда включены и мелкие фиксы.

## Application

Всё начиналось с обёртки `Altrone`/`AltroneApplication`, вокруг которой строилось всё приложение. В 1.3 у неё появился проп `className`, а фокус-стили были приведены к `:focus-visible` в 2.0. Настоящий скачок случился в 2.1 — там дебютировали **Altrone Options**, глобальный механизм настройки поведения всех компонентов сразу (например, отключение анимаций), и HOC `AltroneConfig` для переопределения этих опций для отдельных частей дерева; в 2.2 хук `useThemeContext` был помечен устаревшим в пользу `useAltrone`. В 3.0 механизм донастройки стал ещё гибче: появился `Configuration` — обёртка, позволяющая прокидывать `className`/`style` и другие параметры сразу во все вложенные компоненты, а также проп `customLabels` для переопределения отдельных строк локализации без замены всего словаря. В 4.0 компонент переименован в `Application`, полностью потерял владение раскладкой (`sidebar`/`header` теперь у `Screen`) и лишился самого `Configuration` — глобальный конфиг-слой признан мёртвым кодом, а точечные переопределения делаются через `className`/`style`/CSS-переменные; взамен появился `asChild`. Список поддерживаемых языков расширен до восьми (добавлены упрощённый китайский, португальский, турецкий; исправлены неверные коды `ge`/`sp` → `de`/`es`), а новый проп `icons` позволяет одним разом переопределить встроенные lucide-иконки во всех компонентах библиотеки.

**История по версиям:**

- **4.0 (бета)** — переименован из `AltroneApplication` в `Application`; удалён проп `config`/`useConfiguration()`/`Configuration` (мёртвый код); добавлен `asChild`; добавлен `persistTheme` для сохранения темы между визитами; стал чистым корнем-провайдером — больше не рендерит `Screen` и не владеет `sidebar`/`header`; фон приложения зеркалится на `<body>`/`<html>` (фикс белых полос в Safari); добавлены языки `zh`/`pt`/`tr`, исправлены коды `de`/`es`; добавлен проп `icons` для переопределения встроенных иконок; добавлен `applicationName` и автоматическая синхронизация `document.title` с `Screen.title` (флаг `manageTitle` отключает), плюс императивные `setPageTitle`/`resetPageTitle`
- **3.0.0** — добавлена обёртка `Configuration` для прокидывания `className`/`style` и других параметров во все дочерние компоненты; добавлен проп `customLabels` для переопределения отдельных строк локализации
- **2.2.0** — хук `useThemeContext` помечен устаревшим в пользу `useAltrone`
- **2.1.0** — добавлен механизм **Altrone Options** (глобальные настройки поведения компонентов, например отключение анимаций) и HOC `AltroneConfig` для переопределения опций в поддереве
- **2.0.3** — фокус-стили компонента переведены на `:focus-visible`
- **1.3.4** — исправлено отсутствие пропа `className` у `Altrone`

## Screen

Новый элемент для сборки сложных разметок приложения — с шапкой, сворачиваемым сайдбаром, футером, навигацией или боковой колонкой, да ещё и с адаптацией под разные устройства. Возможность выстраивать разметку вручную никуда не делась — `Screen` остаётся очень гибким. `Screen.Sidebar`/`Screen.Aside` получили управляемый режим (`collapsed`/`defaultCollapsed`), кнопка-переключатель сайдбара в шапке (`Toolbar.SidebarToggleAction`) связывается с сайдбаром без единой строчки состояния на стороне разработчика, а у шапки появился проп `fixed` для возврата её в обычный поток документа.

**История по версиям:**

- **4.0 (бета)** — добавлен как новый компонент: сборка сложных разметок приложения (шапка, сворачиваемый сайдбар, футер, навигация, боковая колонка) с адаптацией под устройства; `Sidebar`/`Aside` получили управляемый режим (`collapsed`/`defaultCollapsed`); `Toolbar.SidebarToggleAction` работает без явной проводки состояния; добавлен `Header.fixed`; добавлены `--top-safe-area`/`--bottom-safe-area`; исправлен z-index `Header`; исправлено схлопывание `Aside`; `Sidebar`/`Drawer`'s `onClose` получил `event`; `title` теперь также питает автоматический `document.title` в `Application`

## Box

До перезапуска дизайн-системы в 3.0 в библиотеке существовал другой `Box` — вспомогательный компонент для отступов на основе хуков `useOffset`/`useMargin`/`usePadding`. Он был помечен устаревшим ещё в 1.3 вместе со всем сопутствующим API (`Offset`, `Margin`, `Padding`, `OffsetAxis` и рядом констант) с прямым предупреждением об удалении в 3.0. С выходом 3.0 отступы и раскладка полностью перешли на новые примитивы (`Flex`, позднее `Grid`), и старый `Box` перестал быть частью публичного API. Новый `Box` дебютировал в 4.0 как строительный блок интерфейса — материал, форма (`shape`), отступы и разные виды интерактивности задаются пропами. Материал `glass` по-настоящему матовый и плотный независимо от `tone`/`color`, штриховка `hatch` переосмыслена в `dotted`, есть непрозрачный материал `pale`, а тон `subtle` убран.

**История по версиям:**

- **4.0 (бета)** — добавлен как новый компонент: строительный блок интерфейса с материалом, формой (`shape`), отступами и интерактивностью; материал `glass` не зависит от `tone`; штриховка `hatch` заменена на `dotted`; добавлен материал `pale`; убран тон `subtle`
- **3.0.0** — старый `Box` и весь сопутствующий API (`useOffset`/`useMargin`/`usePadding`, `Offset`, `Margin`, `Padding`, `OffsetAxis`, константы) удалены из публичного API; отступы и раскладка переехали на `Flex`
- **1.3.1** — возвращены (с пометкой `deprecated`) типы `WithoutDefaultOffsets` и `WithAltroneOffsets`
- **1.3.0** — `Box`, `useOffset`, `useMargin`, `usePadding` и связанные типы/константы помечены устаревшими с предупреждением об удалении в 3.0

## Text

До 3.0 типографику покрывал набор отдельных компонентов — `Heading`, `Paragraph`, `Blockquote` — с точечными фиксами по стилям и пропам (`className`, отступы). В 3.0 все они были заменены единым компонентом `Text` с большим набором сабкомпонентов под разные задачи: `Text.Heading`, `Text.Paragraph`, `Text.Inline`, `Text.Link`, `Text.ScreenName` и другие. В 3.1 у `Text.Heading` проп `role` был помечен устаревшим из-за конфликта с ARIA-семантикой — вместо него добавили `variant` для визуального стиля и отдельный `ariaRole` для явного управления ролью. [в 3.0.3 поправлены фокус-стили `Text.Link`] В 4.0 компонент был переосмыслен: все сабкомпоненты (`Text.Heading`, `Text.Paragraph`, `Text.Inline`, `Text.Link` и др.) убраны в пользу большого набора дискриминирующих пропов, расширена шкала размеров, добавлена обрезка текста и новые возможности для ссылок.

**История по версиям:**

- **4.0 (бета)** — убраны все сабкомпоненты в пользу дискриминирующих пропов; расширена шкала размеров; добавлена обрезка текста; новые возможности для ссылок
- **3.1.0** — у `Text.Heading` проп `role` помечен устаревшим (конфликт с ARIA), добавлены `variant` и `ariaRole`
- **3.0.3** — исправлены фокус-стили `Text.Link`
- **3.0.0** — компонент `Text` заменил `Heading`/`Paragraph`/`Blockquote`; добавлены сабкомпоненты `Text.Heading`, `Text.Paragraph`, `Text.Inline`, `Text.Link`, `Text.ScreenName` и другие
- **2.0.4** *(`Heading`)* — исправлено переопределение `className`; исправлено отсутствие пропа `id`
- **2.0.3** *(`Blockquote`)* — исправлен `padding-right`
- **1.3.2** *(`Blockquote`)* — исправлен обязательный проп `className`
- **1.3.1** *(`Blockquote`)* — исправлен родительский интерфейс
- **1.0.4** *(`Blockquote`)* — убрана реализация через старый `Box`

## Grid

Появился в 3.3 как более мощная альтернатива `Flex` для сложных раскладок: 12-колоночная сетка с поддержкой отступов между колонками и гибкой конфигурацией. В 4.0 улучшена формула расчёта размера колонок, добавлены отступы между строками и колонками, исправлена логика переноса колонок на новую строку, а проп `tagName` заменён на `asChild`.

**История по версиям:**

- **4.0 (бета)** — улучшена формула расчёта размера колонок; добавлены отступы между строками/колонками; исправлена логика переноса на новую строку; `tagName` заменён на `asChild`
- **3.3.0** — добавлен как новый компонент: 12-колоночная сетка с настраиваемыми отступами между колонками и гибкой конфигурацией

## Flex

Один из базовых layout-примитивов, добавленных при перезапуске в 3.0 — замена старого `ButtonContainer`, решающая задачу выравнивания элементов в ряд или колонку с управлением направлением и отступами. В 4.0 добавлены унифицированные размеры отступов между дочерними элементами, `direction` переименован в `orientation`, `tagName` — в `asChild`, а `align` переведён на общий тип `Align`.

**История по версиям:**

- **4.0 (бета)** — добавлены унифицированные размеры отступов между дочерними элементами; `direction` → `orientation`; `tagName` → `asChild`; `align` переведён на общий тип `Align`
- **3.0.0** — добавлен как новый компонент-примитив (замена `ButtonContainer`) для выравнивания элементов в ряд/колонку с управлением направлением и отступами

## Drawer

Новый компонент, рисующий выезжающую панель — слева или справа. Удобен для карточек создания, редактирования или просмотра больших объёмов данных, со встроенными механизмами шапки и кнопок действий. Дровер построен на общем с `Modal` фундаменте `Sheet` — это даёт блокировку скролла страницы и защиту от iOS-клавиатуры, перекрывающей панель; открытие управляется только через `open`/`onClose` (проп-триггер в `children` убран), есть `dismissible` и `showCloseButton`, а экшены передаются в пропы `actions`/`additionalActions`.

**История по версиям:**

- **4.0 (бета)** — добавлен как новый компонент: выезжающая слева/справа панель со встроенной шапкой и кнопками действий; построен на фундаменте `Sheet` (блокировка скролла, защита от iOS-клавиатуры); открытие только через `open`/`onClose`; добавлены `dismissible`, `showCloseButton`; экшены через `actions`/`additionalActions`; императивный метод `close` → `hide`; дефолтная кнопка «Готово» — текст вместо иконки

## Popover

До 3.0 всплывающими контейнерами занимался `FloatingBox` — он получил `surface` и `elevation`, настройку отступов от границ окна (2.0–2.2), но в целом развивался медленно, а проп `popperProps` был помечен устаревшим ещё в 2.2. В 3.0 на смену ему пришёл `Popover`, построенный на более современных библиотеках позиционирования: добавилась поддержка заголовка и кнопки закрытия, управление фокусом, выбор типа триггера. [в 1.0.5 исправлена работа при `parentElement = null`, в 3.0.3 — недоступность дочернего элемента для фокуса] В 4.0 добавлена новая анимация появления, улучшено позиционирование, добавлен режим отображения поверх компонента-источника, убрана встроенная стрелка. `ref` стал настоящим DOM-ref триггера, а весь императивный API (`show`/`hide`, ранее `openPopup`/`closePopup`) переехал в `controlRef`; добавлен полноценный управляемый режим `open`/`onOpenChange`.

**История по версиям:**

- **4.0 (бета)** — новая анимация появления; улучшено позиционирование; добавлен режим отображения поверх компонента-источника; убрана встроенная стрелка; `ref` теперь указывает на DOM-элемент триггера; императивный API (`show`/`hide`, ранее `openPopup`/`closePopup`) переехал в `controlRef`; добавлен управляемый режим `open`/`onOpenChange`
- **3.5.0** — исправлены некорректные типы `children`/`content` для отдельных случаев
- **3.0.3** — исправлена недоступность дочернего элемента для фокуса
- **3.0.0** — `Popover` заменил `FloatingBox`: добавлены заголовок, кнопка закрытия, управление фокусом, выбор типа триггера, более современная библиотека позиционирования
- **2.2.0** *(`FloatingBox`)* — проп `popperProps` помечен устаревшим
- **2.0.0** *(`FloatingBox`)* — добавлены `surface`, `elevation`, настройка отступов от границ окна
- **1.3.0** *(`FloatingBox`)* — исправлено некорректное расширение интерфейса
- **1.0.5** *(`FloatingBox`)* — исправлена потенциальная проблема при `parentElement = null`; изменён тип пропа `minWidth`

## Dropdown

Предшественником был `ContextMenu` — он умел `fluid`-режим, ограничение `maxHeight`, выделение выбранного пункта (`selected`), а в 2.2 получил чекбокс- и радио-варианты пунктов списка и возможность вставлять произвольные элементы через `elementAbove`/`elementBelow`. В 3.0 его заменил `Dropdown` с поддержкой бесконечной вложенности меню и произвольных компонентов внутри списка. В 3.4 добавили проп `badge` для пункта-действия (`Dropdown.Action`). [в 2.1.3 исправлена ширина на мобильных устройствах, в 2.2.1 — баг с одновременным открытием нескольких дочерних меню] В 4.0, вслед за `Popover`, API компонента доработан, а колбэки стали получать нативные объекты событий. `Dropdown.Menu` получил проп `maxHeight` — теперь длинный список можно ограничить и прокручивать без ручной обёртки в `Scrollable`.

**История по версиям:**

- **4.0 (бета)** — унаследовал улучшения `Popover`; доработан API; колбэки получили нативные объекты событий (в т. ч. `Dropdown.Checkbox`/`.RadioList.onChange`); добавлен `maxHeight` для `Dropdown.Menu` (авто-скролл длинного списка)
- **3.4.0** — добавлен `badge` для `Dropdown.Action`; новые CSS-переменные для бейджа; исправлены некорректные типы
- **3.0.0** — `Dropdown` заменил `ContextMenu`: бесконечная вложенность меню, произвольные компоненты внутри списка
- **2.2.1** *(`ContextMenu`)* — исправлен баг с одновременным открытием нескольких дочерних меню
- **2.2.0** *(`ContextMenu`)* — добавлены чекбокс- и радио-варианты пунктов списка; добавлены `elementAbove`/`elementBelow`
- **2.1.3** *(`ContextMenu`)* — исправлена ширина на мобильных устройствах
- **2.0.0** *(`ContextMenu`)* — добавлены `fluid`, `maxHeight`, `selected` для пункта меню

## Tooltip

Формально выделен в отдельный компонент в 3.0 как облегчённый вариант `Popover` — заточенный именно под тултипы. До этого всплывающие подсказки существовали как часть `FormField` (см. `Form`). В 3.1 поправлен тип пропа `children` и внесены улучшения доступности. В 4.0 тултип избавился от лишних возможностей `Popover` и получил специфичные для себя `title` и отображение горячей клавиши. Появился `trigger` (наведение/фокус/клик), управляемый режим `defaultOpen`/`onOpenChange`, а `childrenClassName` переименован в `triggerClassName`.

**История по версиям:**

- **4.0 (бета)** — убраны лишние возможности `Popover`; добавлены `title` и отображение горячей клавиши; добавлен `trigger` (hover/focus/click); управляемый режим `defaultOpen`/`onOpenChange`; `childrenClassName` → `triggerClassName`
- **3.1.0** — исправлен тип пропа `children`; улучшения доступности
